Thanks for #3. One more thing on the `method = "sample"` path that the issue doesn't cover yet: a gene set sitting entirely at the bottom of the ranked list (ES = -1) always gets the permutation floor, p = 1/(nPerm + 1), however many permutations are run.

```r
library(enrichit)
set.seed(1)
stats <- sort(setNames(rnorm(24), sprintf("g%02d", 1:24)), decreasing = TRUE)
gs <- list(S = names(stats)[22:24])          # the three lowest-ranked genes, ES = -1
r <- as.data.frame(gsea(stats, gs, minGSSize = 1, maxGSSize = 23,
                        method = "sample", nPerm = 2e5, seed = 5, verbose = FALSE))
c(ES = r$enrichmentScore, p = r$pvalue)
#>            ES             p
#> -1.000000e+00  4.999975e-06
```

Enumerating all 2,024 three-gene sets gives an exact same-sign p of about 0.001 for this set (0.0008 to 0.0018 over five random lists). `permute` gives 4.4e-04 and `multilevel` 8.2e-04 on the same set. The top three genes (ES = +1) don't hit the floor; there it's only the halving described above.

As far as I can tell, the cause is that on the `sample` path the observed ES is computed by `calculate_es_details()` while the permutation scores come from `calculate_es_sparse()`. For ES = -1 the two differ in the last bits, so no permutation ever counts as being as extreme as the observed value. Comparing the observed ES computed with `calculate_es_sparse()` fixes it.

I have a branch with both fixes (the same-sign denominator from #3 and this one), plus a test that checks `sample`, `permute` and `adaptive` against the exact enumeration on a small example. The test fails on devel and passes with the fix. Happy to open it as a PR that closes #3 if that would help.
