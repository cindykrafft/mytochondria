Title: gsea(method = "sample" | "permute") and adaptive = TRUE report p-values about half of the GSEA convention (denominator counts all permutations, not the same-sign ones)

<!-- YuLab-SMU/enrichit has no issue template; written in the order of clusterProfiler's .github/issue_template.md -->

### Prerequisites

- [x] latest release checked: enrichit 0.2.1 (CRAN) and `devel` `a261244` (0.2.2) behave the same; 0.1.4 and 0.2.0 too
- [x] documentation read (`?gsea`: "pvalue: Empirical p-value from permutation test")
- [x] tracker searched (no prior report; enrichit #1 is about NA rows)

### Describe your issue

**Expected:** for a gene set with observed enrichment score ES, `gsea(method = "sample")`,
`gsea(method = "permute")` and `gsea(adaptive = TRUE)` return the GSEA nominal p-value of
Subramanian et al. 2005 — the fraction of permutation scores *of the same sign as ES* that are at
least as extreme — which is what `method = "multilevel"`, fgsea (`(1 + nGeEs) / (1 + nGeZero)`) and
DOSE's old permutation path (`sum(perm >= NES) + 1) / (sum(perm >= 0) + 1)`) compute.

**Got:** `src/gsea.cpp:339` (and `:517`, `:536` for the adaptive path) divides by `nPerm + 1`, i.e.
by all permutations. Since about half of the permutation scores have the other sign, the reported p
is about half of the multilevel p for the same set. On 24 genes and sets of 3, where the null can be
enumerated exactly (2,024 sets), a set with ES = 0.381 has exact same-sign p = 0.882;
`method = "sample"` with 2e5 permutations returns 0.446, `multilevel` 0.879. Over 14 sets on three
tiny designs the median ratio of the `sample` p to the exact same-sign p is 0.50 (0.005–1.21), of the
`permute` p 0.59 and of the adaptive p 0.50, while `multilevel` gives 1.04 (0.99–1.25) and fgsea
1.05. Shrinking the example showed a second, smaller problem on the `sample` path: the observed ES is
computed by the dense loop (`calculate_es_details`) and the permutation scores by the block loop
(`calculate_es_sparse`), and for a set lying entirely at one end of the list (ES = ±1) the two
roundings differ so that no permutation is ever counted and p = 1/(nPerm + 1) is reported (5e-6
where the exact value is 5e-4).

The default `multilevel` method is unaffected; this only reaches users who ask for `sample`,
`permute` or `adaptive = TRUE` (through `clusterProfiler::GSEA(method = ...)` as well).

**Proposed fix:** count the same-sign permutations and use `(count_better + 1) / (count_same_sign + 1)`,
capped at 1, in `gsea()` and `gsea_adaptive()`, and compare the observed ES through
`calculate_es_sparse` on the `sample` path. A patch with a regression test against the exact
enumeration (fails on `devel`, passes with the fix) and a NEWS entry is ready; PR follows if wanted.

### Reproducible example

```r
library(enrichit)   # 0.2.2 (devel a261244); same on CRAN 0.2.1
set.seed(124)
stats <- sort(rnorm(24), decreasing = TRUE); names(stats) <- sprintf("g%02d", 1:24)
es_of <- function(idx) { hits <- seq_along(stats) %in% idx
  rs <- cumsum(ifelse(hits, abs(stats), 0)) / sum(abs(stats[hits])) - cumsum(!hits) / (24 - length(idx))
  if (abs(max(rs)) >= abs(min(rs))) max(rs) else min(rs) }
null <- apply(combn(24, 3), 2, es_of)                       # exact null: every gene set of size 3
set <- list(mid = names(stats)[c(8, 12, 16)]); es <- es_of(c(8, 12, 16))
p_same_sign <- mean(null[null >= 0] >= es)                   # GSEA convention
p_all <- mean(null >= es)                                    # what the code computes
r <- suppressWarnings(gsea(stats, set, minGSSize = 1, maxGSSize = 23, method = "sample", nPerm = 2e5, seed = 5, verbose = FALSE))
m <- suppressWarnings(gsea(stats, set, minGSSize = 1, maxGSSize = 23, method = "multilevel", eps = 0, seed = 7, verbose = FALSE))
cat(sprintf("ES = %.4f; exact same-sign p = %.4f; exact P(ES* >= ES) over all sets = %.4f\n", es, p_same_sign, p_all))
cat(sprintf("sample p = %.4f   multilevel p = %.4f\n", r$pvalue, m$pvalue))
stopifnot(abs(r$pvalue - p_same_sign) < 0.05)   # expected to pass
```
