# Issue: bidiphase.shift corrupts odd scan lines on torch tensors (v1.0+)

**Target:** `MouseLand/suite2p` (issue, then PR)

## Title

```
BUG: bidiphase correction corrupts odd scan lines since the torch registration path (v1.0.0.1)
```

## Body

```markdown
**Describe the bug**

`suite2p/registration/bidiphase.py::shift` moves the odd lines with an in-place assignment whose source and destination slices overlap:

    if bidiphase > 0:
        frames[:, 1::2, bidiphase:] = frames[:, 1::2, :-bidiphase]

numpy makes a temporary copy for overlapping assignments, but `torch.Tensor.copy_` does not, so on a torch tensor the assignment reads pixels it has already overwritten. Since v1.0.0.1 `register_frames` (register.py line 613) and `shift_frames_and_write` (line 756) pass torch tensors to `bidi.shift`, so with `do_bidiphase=True` (or a nonzero `bidiphase`) every frame's odd lines are corrupted instead of shifted. The reference image still goes through the numpy path in `registration_wrapper` (line 931), so it *is* shifted correctly, and frames and reference disagree.

**Reproduction (suite2p 1.1.0, torch 2.13, CPU):**

    import numpy as np, torch
    from suite2p.registration import bidiphase as bidi
    fr = np.arange(2*4*8, dtype=np.int16).reshape(2, 4, 8)
    print(bidi.shift(fr.copy(), 3)[0, 1])                    # numpy:  [ 8  9 10  8  9 10 11 12]
    print(bidi.shift(torch.from_numpy(fr.copy()), 3)[0, 1])  # torch:  [ 8  9 10  8  9 10  8  9]

End-to-end through `register_frames` with identical frames (zero motion) and `bidiphase=3`, 34 % of odd-line pixels differ from the intended shift. Script: https://github.com/cindykrafft/research-software-audit/blob/main/audits/suite2p/verify/s2_bidiphase_torch.py

**Fix**

Copy the source slice before the assignment (`.clone()` for torch, `.copy()` for numpy). PR to follow; validated that odd lines are then exact for positive and negative offsets.
```
