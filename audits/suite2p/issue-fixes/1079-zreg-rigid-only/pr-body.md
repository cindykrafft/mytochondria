Title: compute_shifts: return None nonrigid offsets for rigid-only multi-reference registration

Fixes #1079 (part 1).

Registering against a list of reference images (the z-registration path that produces `ops["zpos_registration"]`) crashes when `nonrigid=False`:

```
File "suite2p/registration/register.py", line 459, in shift_frames
    fr_torch = nonrigid.transform_data(fr_torch, blocks[2], blocks[1], blocks[0],
IndexError: list index out of range
```

**Cause.** For `nZ > 1`, `compute_shifts` always builds six offset tensors, so the nonrigid entries come back as zero-width tensors of shape `(n_frames, 0)` instead of `None`. `shift_frames` then takes `yoff1 is not None` as "apply nonrigid shifts" and calls `nonrigid.transform_data` with the empty block list that `register_frames` gets when `block_size=None`. The `nZ == 1` branch returns `None` for these entries when nonrigid registration is off.

**Fix.** In the `nZ > 1` branch, only assemble the three rigid offsets when the reference has no nonrigid masks and return `None` for the nonrigid ones, matching the single-reference path. No change for `nonrigid=True` or for single-reference registration.

**Test.** `tests/test_registration.py::test_register_frames_with_reference_list_rigid_only` registers a 6-frame synthetic movie against two reference images with `nonrigid=False` and `nonrigid=True`; the `False` case fails on `main` with the `IndexError` above and passes with this change.

**Run.** `pytest tests/test_registration.py`: 3 passed, 1 skipped (MPS), 1 failed before; 4 passed, 1 skipped after. `registration_wrapper` end to end with a two-image reference list, one and two channels, `nonrigid` on and off, completes and returns `zpos_registration` (`repro_wrapper.py` in the project directory). Part 2 of #1079 (two channels, `nonrigid=True`, reported on v0.14.2) already runs on `main`.
