Title: quant -b N --plaintext -t T (T > 1) writes no bootstraps when kallisto is built without HDF5, and run_info.json still reports N

<!-- pachterlab/kallisto has no issue template. First filing (with a PR against devel). -->

**Versions:** 0.52.0 (`master` @ 4e9f29c, `devel` @ 34aba49), 0.51.1 and 0.50.1, each built with the default `cmake ..` (`USE_HDF5=OFF`); also the 0.48.0 Linux release binary. Builds with HDF5 behave correctly: the 0.46.1 and 0.50.1/0.51.1/0.52.0 release binaries, and `-DUSE_HDF5=ON`.

In the `quant` branch of `main.cpp` the multi-threaded bootstrap step is compiled only with HDF5:

```cpp
if (opt.threads > 1) {
  ...
#ifdef USE_HDF5
  BootstrapThreadPool pool(opt.threads, seeds, collection.counts, index, collection,
                           em.eff_lens_, opt, &writer, fl_means);
#endif
} else {
  for (auto b = 0; b < B; ++b) { ... }   // writes bs_abundance_b.tsv with --plaintext
}
```

Without HDF5, `CheckOptionsEM` keeps `-b` only with `--plaintext` ("Run quant with --plaintext option or recompile with HDF5 support to obtain bootstrap estimates"). With `--plaintext` and more than one thread, the branch above is empty: no bootstrap runs, nothing is printed, the exit status is 0, and `run_info.json` reports the requested number of bootstraps.

**Reproduction** with the repository's `test/` data, kallisto built from `master` with `cmake ..`:

```
$ kallisto index -i t.idx test/transcripts.fasta.gz
$ kallisto quant -i t.idx -o out_t1 -b 10 --plaintext -t 1 test/reads_1.fastq.gz test/reads_2.fastq.gz
exit 0
$ ls out_t1; grep n_bootstraps out_t1/run_info.json
abundance.tsv bs_abundance_0.tsv bs_abundance_1.tsv ... bs_abundance_9.tsv run_info.json
	"n_bootstraps": 10,

$ kallisto quant -i t.idx -o out_t4 -b 10 --plaintext -t 4 test/reads_1.fastq.gz test/reads_2.fastq.gz
...
[quant] processed 10,000 reads, 9,413 reads pseudoaligned
[quant] estimated average fragment length: 178.02
[   em] quantifying the abundances ... done
[   em] the Expectation-Maximization algorithm ran for 52 rounds
exit 0
$ ls out_t4; grep n_bootstraps out_t4/run_info.json
abundance.tsv run_info.json
	"n_bootstraps": 10,
```

The same happens on 0.50.1 and 0.51.1 built from their tags, and with the 0.48.0 release binary (0 of 8 bootstrap tables with `-t 2` and `-t 4`, 8 of 8 with `-t 1`). The `#ifdef` appeared when HDF5 became optional; 0.46.1 compiles the pool unconditionally. Bioconda and Homebrew build with `-DUSE_HDF5=ON` and are not affected, but a source build following INSTALL.md is. Debian's packaging (`debian/rules` for 0.51.1+dfsg) passes no `-DUSE_HDF5`, so its package should be affected too. I have not run the Debian binary itself.

**Fix:** `BootstrapThreadPool` and `BootstrapWorker` do not depend on HDF5. With `--plaintext` the worker writes `bs_abundance_<id>.tsv` itself, so the pool can be constructed in every build, with the HDF5 writer passed only when there is one. With that change the `-t 4` run writes all ten tables, identical to the `-t 1` tables (the seeds are drawn before the branch). The abundance estimates are unchanged. PR follows against `devel`, with a functional test in `func_tests/runtests.sh`.
