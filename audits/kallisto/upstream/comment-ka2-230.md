This is the single-end filter in `ProcessReads.cpp` (around line 1162 on 0.52.0). Unless `--single-overhang` is given, a target is removed from a read's pseudoalignment when the read's start plus the mean fragment length `-l` would run past the target's end (forward reads), or before its start (reverse reads). A read that lies only on such targets is not pseudoaligned. So with `-l 200` no read can count towards a target of 200 bp or shorter, and a read starting in the last `-l` bases of a longer target is dropped from it.

A side effect matters for TPMs: the effective length kallisto divides by is still `L - mu_L + 1`, with `mu_L` the mean of the Gaussian(`-l`, `-s`) truncated at `L`. That length assumes fragments shorter than `-l` were counted. With reads simulated under kallisto's own model (equal true TPM for every target, `--single -l 200 -s 20`, 75-bp reads):

| target length | reads simulated | est_counts (default) | est_counts (`--single-overhang`) |
|---|---|---|---|
| 150 | 56 | 0 | 56 |
| 180 | 105 | 0 | 105 |
| 200 | 126 | 9 | 126 |
| 220 | 225 | 173 | 225 |
| 250 | 395 | 348 | 395 |
| 4000 | 29240 | 29165 | 29240 |

With `--single-overhang` every count matches the simulation (0.46.1 through 0.52.0 behave the same). By default, targets up to `-l` get TPM 0, those up to roughly `-l + 2·sd` come out low, and the other targets' TPMs rise to absorb the difference. Either making the effective length count only the start positions the filter keeps, or including these reads by default, would make the two consistent. Separately, the forward test (`x.first + fl <= target_len`, with 1-based `x.first`) also drops the last valid start position; the reverse test is exact.
