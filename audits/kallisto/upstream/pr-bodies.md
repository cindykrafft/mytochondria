### PR 1 — `fix/bootstrap-threads-without-hdf5` — "Run multi-threaded bootstraps in builds without HDF5"

Fixes #NNN.

In `kallisto quant`, the multi-threaded bootstrap step (`BootstrapThreadPool`) was compiled only `#ifdef USE_HDF5`. In a build without HDF5, which is the CMake default, `-b N --plaintext -t T` with `T > 1` therefore ran no bootstraps. No `bs_abundance_*.tsv` was written, nothing was printed, the exit status was 0, and `run_info.json` still reported `n_bootstraps: N`. With `-t 1` the same build wrote all N tables.

The pool and its workers do not need HDF5. Without it, `CheckOptionsEM` keeps bootstraps only with `--plaintext`, and the workers then write the plaintext tables themselves. This change constructs the pool in every build, passes the HDF5 writer only when it exists, and passes `n_threads`, which the warning just above already caps at the number of bootstraps. It also adds a functional test that runs `quant -t 2 -b 2 --plaintext` on `basic7.idx` and checks that both tables are written.

Checked on builds with and without `-DUSE_HDF5=ON`:

- with `-t 2` and `-t 4` every bootstrap table is written, identical to the `-t 1` tables for the same `--seed`;
- `abundance.tsv` is unchanged;
- `func_tests/runtests.sh` gives the same results as `devel`, except for the new test, which fails without the change on the non-HDF5 build.

One existing check fails on both: the last d-list `bustools text ... | cut -f3` md5 with bustools `d4d7a28`.
