Title: featureCounts --splitOnly counts non-split fragments whose mate is unmapped (read-pair mode)

**Version:** featureCounts v2.1.1 (SourceForge source tarball), also v2.0.3 and v2.0.1, and GitHub `master` (`55dc154`, v2.0.6); Linux x86_64, built with `make -f Makefile.Linux`.

**Command:** `featureCounts -p --countReadPairs --splitOnly -a a.gtf -o out a.sam`

**Expected:** with `--splitOnly`, "only split alignments (CIGAR strings contain letter 'N') will be counted. All the other alignments will be ignored" (users guide, option table). None of the fragments in the example below has an N, so gene A should get 0 and every fragment should be `Unassigned_NonSplit`.

**Got:** gene A = 2. The fragment whose first read is a non-split `40M` alignment and whose mate is unmapped, and the single-end record (`40M`), are both `Assigned`; only the proper pair with two non-split reads is `Unassigned_NonSplit`. On a larger file, 1,000 of 1,000 non-split singleton fragments inside one gene are counted (0 of 200 non-split proper pairs). `--nonSplitOnly` and read-level counting (`-p --splitOnly` without `--countReadPairs`) behave as documented.

**Why:** in read-pair mode `process_line_buffer` walks the two records of a fragment. An unmapped record leaves the loop at `if(SAM_FLAG_UNMAPPED & alignment_masks) continue;` (`readSummary.c:3134` on `master`) before the `--splitOnly` test at `:3190-3206`, which counts mapped non-split records in `skipped_for_exonic` and drops the fragment only when that counter reaches `1 + is_paired_end_mode_assign` = 2. A fragment with one mapped non-split record and an unmapped mate reaches 1; so does a single-end record in a paired-end file, whose missing mate is an unmapped placeholder. Shrinking the example showed that exactly one mapped non-split record with no mapped mate is enough; the annotation, the strand and the mate's position do not matter.

**Proposed fix:** count an unmapped record as a non-split record in read-pair mode before the `continue`, so a fragment is excluded when none of its mapped records is split. A patch that does this, moves the `Unassigned_NonSplit`/`Unassigned_Split` bookkeeping into one helper and adds `test/featureCounts/data/corner-SPLITONLY.{sam,ora}` (expected `simu_gene1 = 3`; the current code gives 8) is ready; the full `featureCounts-test.sh` suite passes with it.

**Minimal reproduction** (Python 3, no dependencies; pass the path to the binary):

```python
#!/usr/bin/env python3
import subprocess, sys, tempfile
fc = sys.argv[1] if len(sys.argv) > 1 else "featureCounts"
d = tempfile.mkdtemp()
open(f"{d}/a.gtf", "w").write('chr1\tx\texon\t1000\t1400\t.\t+\t.\tgene_id "A";\n')
S = "A" * 40; Q = "I" * 40
open(f"{d}/a.sam", "w").write(
    "@HD\tVN:1.6\tSO:unsorted\n@SQ\tSN:chr1\tLN:10000\n"
    f"frag1\t73\tchr1\t1100\t60\t40M\t=\t1100\t0\t{S}\t{Q}\n"      # first read mapped, no N; mate unmapped
    f"frag1\t133\tchr1\t1100\t0\t*\t=\t1100\t0\t{S}\t{Q}\n"
    f"se1\t0\tchr1\t1100\t60\t40M\t*\t0\t0\t{S}\t{Q}\n"           # single-end record, no N
    f"pair1\t99\tchr1\t1100\t60\t40M\t=\t1300\t240\t{S}\t{Q}\n"    # proper pair, no N (control)
    f"pair1\t147\tchr1\t1300\t60\t40M\t=\t1100\t-240\t{S}\t{Q}\n")
subprocess.run([fc, "-p", "--countReadPairs", "--splitOnly", "-a", f"{d}/a.gtf", "-o", f"{d}/out", f"{d}/a.sam"],
               check=True, capture_output=True)
count = [l for l in open(f"{d}/out") if l.startswith("A\t")][0].split("\t")[-1].strip()
summ = {l.split("\t")[0]: l.split("\t")[1].strip() for l in open(f"{d}/out.summary")}
print(f"count for gene A = {count} (expected 0); Assigned={summ['Assigned']} Unassigned_NonSplit={summ['Unassigned_NonSplit']}")
```

Output on v2.1.1, v2.0.3, v2.0.1 (`-p`) and `master`:

```
count for gene A = 2 (expected 0); Assigned=2 Unassigned_NonSplit=1
```

With the patch: `count for gene A = 0 (expected 0); Assigned=0 Unassigned_NonSplit=3`.
