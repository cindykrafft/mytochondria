Title: Fix PC features for final clusters that share a detection template

Fixes #1039.

## What

`postprocessing.make_pc_features` loops over final clusters and, for each one, calls `get_data_cpu` with the *full* `spike_templates` and `tF` arrays, selecting every spike whose detection template belongs to the cluster. When several final clusters share a detection template (a template that was split, or spikes reassigned during merging), that selection also picks up the other clusters' spikes, and the in-place write `tF[igood, :] = Xd[:, ind[:n_chans], :]` re-orders their channel columns too. When the other cluster comes up in the loop its rows are read as if they were still in the original `iC` channel order, so they are re-ordered a second time from the wrong starting point. The exported `pc_features` / `pc_feature_ind` for that cluster then no longer correspond to each other, and the result depends on the order in which clusters happen to be visited.

The reporter's minimal example (two clusters, one shared template, two channels, both clusters largest on channel 1) gives `pc_feature_ind = [[1, 0], [0, 1]]` on `main`, and scattering `pc_features` back onto those channel ids does not reproduce the input features.

## Fix

Restrict the spike selection, the channel ranking and the in-place update to the spikes of the current cluster (`cluster_spikes = np.flatnonzero(spike_clusters == i)`), and map `igood` back through `cluster_spikes` when writing into `tF`. This matches the docstring's intent ("features are associated with the final clusters instead of templates"). Clusters that do not share a template with any other cluster produce byte-identical output to before (checked on random data against the unmodified function); for clusters that do share templates the output is now independent of cluster order.

Same approach as the fix the reporter (@gwfolk) prototyped in their fork.

## Test

`tests/test_postprocessing.py` (new):
- `test_make_pc_features_shared_template` — the reporter's example; asserts `pc_feature_ind == [[1, 0], [1, 0]]` and that the exported features map back onto the input. Fails on `main`, passes with the fix.
- `test_make_pc_features_order_independent` — relabelling the clusters permutes `pc_feature_ind` and leaves `pc_features` unchanged.
