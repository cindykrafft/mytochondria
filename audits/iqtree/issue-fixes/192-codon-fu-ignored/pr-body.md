Title: Honour user-defined codon frequencies (+FU) for GY-type models (#192)

Fixes #192.

`ModelCodon::init` replaced a user-defined frequency type with the model's default whenever the model was mechanistic:

```cpp
if (freq == FREQ_USER_DEFINED && def_freq != FREQ_USER_DEFINED) // mechanistic model
    freq = def_freq;
```

For the MG family that is what makes `+FU` fall back to `F3X4`, which those models require (their frequencies are nucleotide-targeted). `initGY94()` however returns `FREQ_EMPIRICAL` as its default, so a `GY{...}+FU{f1,...,f61}` request became `GY+F`: the 61 supplied values were never read, the report said `GY+F` with 60 free parameters, and every `+FU` vector gave the same log-likelihood. 2.4.0 honoured the request (`GY+FU`, 0 free parameters), as the issue shows.

The override now applies only to models whose frequencies are nucleotide-targeted (`codon_freq_style == CF_TARGET_NT`, the MG family), so GY-type models take the user's codon frequencies as before. MG behaviour is unchanged (`MG+FU{...}` still becomes `MG+F3X4`).

Verification on a 4-taxon, 60-codon alignment with a fixed tree and `-blfix` (reproduction script and data in the linked repository):

| model | before | after |
|---|---|---|
| `GY{0.8,1.07}+FU{skewed}` | −648.1018, `GY+F`, 60 free parameters | −674.5579, `GY+FU`, 0 |
| `GY{0.8,1.07}+FU{uniform}` | −648.1018, `GY+F`, 60 free parameters | −667.8904, `GY+FU`, 0 |
| `GY{0.8,1.07}+F3X4`, `GY+F`, `MG{0.8}+F3X4` | unchanged | unchanged |

Both `+FU` values after the fix agree to all printed digits with an independent GY94 likelihood computed in numpy from the same frequencies, tree and parameters (−674.55787, −667.89043).

Test: `test_iqtree.sh` / `test_iqtree.ps1` gain a `GY+FU` run on a small codon alignment (`test_scripts/test_data/codon.fa`, `codon.tree`, `codon_freq.txt`) and a `GY+F3X4` control, with their log-likelihoods in `expect_ans.txt`; on unmodified master the `+FU` row fails by 26 log-likelihood units.
