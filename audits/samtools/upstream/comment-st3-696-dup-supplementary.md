To answer the question eight years on: yes, both `samtools markdup -S` and Picard MarkDuplicates set the duplicate flag on the supplementary records of a duplicate, and `stats` still counts them (the `IS_DUP` block sits before the `IS_ORIGINAL` check in `collect_stats()`, as in the two links above). `sequences` and `total length` exclude secondary and supplementary records, so `reads duplicated / sequences`, which MultiQC prints as the duplication rate from `samtools stats`, is overstated. Two pairs, both duplicates, one supplementary record flagged like its primary:

```sh
A=$(printf 'A%.0s' $(seq 100)); Q=$(printf 'I%.0s' $(seq 100))
printf '@HD\tVN:1.4\tSO:coordinate\n@SQ\tSN:ref\tLN:100000\n' > dup.sam
for i in 0 1; do p=$((1000 + i * 1000))
  printf 'p%d\t1123\tref\t%d\t60\t100M\t=\t%d\t300\t%s\t%s\n' $i $p $((p + 200)) "$A" "$Q" >> dup.sam
  printf 'p%d\t1171\tref\t%d\t60\t100M\t=\t%d\t-300\t%s\t%s\n' $i $((p + 200)) $p "$A" "$Q" >> dup.sam
done
printf 'p0\t3219\tref\t9000\t60\t30M70H\t=\t1000\t0\t%s\t%s\n' "$(printf 'A%.0s' $(seq 30))" "$(printf 'I%.0s' $(seq 30))" >> dup.sam
samtools stats dup.sam | grep -E '^SN.(sequences|reads duplicated|supplementary alignments|total length|bases duplicated):'
```

Output on `develop` (de749a6), 1.19.2, 1.10 and 1.9:

```
SN	sequences:	4
SN	reads duplicated:	5	# PCR or optical duplicate bit set
SN	supplementary alignments:	1
SN	total length:	400	# ignores clipping
SN	bases duplicated:	430
```

so 125 % of the sequences are "duplicated". On a larger synthetic file (1,000 pairs, 20 % duplicate pairs, every other pair with a supplementary record of read 2 flagged like its primary) `reads duplicated / sequences` comes out at 25.0 % where the primary-read duplication rate is 20.0 %; `flagstat` prints both `duplicates` (500) and `primary duplicates` (400), `stats` has only the one line.

A PR follows that makes exactly the move suggested here (the `IS_DUP` block inside the `IS_ORIGINAL` block, next to the read length counts), with `test/stat/22_dup_supp.sam` as a regression test that fails on unmodified `develop`; the same branch carries a second, one-line commit for `insert size standard deviation`, whose loop starts at bin 1 while the mean and the count include bin 0, so pairs with TLEN 0 lower the SD instead of raising it (three pairs with TLEN 300, 300, 0: mean 200.0, SD reported 81.6, population SD 141.4).
