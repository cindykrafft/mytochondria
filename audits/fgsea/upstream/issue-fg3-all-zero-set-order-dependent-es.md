Thanks for fgsea. I have a question about one corner case, plus a small proposal.

When every gene of a pathway that is present in `stats` has a statistic of exactly 0, `calcGseaStat()` gives the members equal weights (the `NR == 0` branch, "equivalent to rAdj being rep(eps, m)"). That limit makes sense. The ES then depends only on where the block of zeros sits in the ranking and on the order of the members inside it. Because tied genes keep their input order, the ES changes with the order of the input vector. `prepareStats()` leaves zeros out of the ties check (`ties <- sum(duplicated(stats[stats != 0]))`), so no warning appears in this case. The check is right for every other pathway, because zero-weight genes do not move the ES when the total weight is positive.

Lists with many exact zeros are common when every gene is ranked, for example by a log fold change that is 0 for genes detected in neither group, or by DESeq2/limma statistics with `NA` replaced by 0.

### Reproducible example

```r
library(fgsea)
set.seed(5)
n <- 20000; g <- sprintf("G%05d", 1:n)
st <- setNames(c(rnorm(n - 6000, 0, 0.6), rep(0, 6000)), g)   # 6,000 genes with stat exactly 0
st <- st[sample(n)]
zero <- names(st)[st == 0]
S <- zero[2001:2100]                     # 100 zero-stat genes that are adjacent in the input vector
run <- function(stats) { set.seed(1); fgsea(list(S = S), stats)[, .(ES, NES, pval)] }
cbind(order = c("as given", "set moved first", "set moved last", "shuffled"), rbind(run(st),
      run(st[order(names(st) %in% S, decreasing = TRUE)]),
      run(st[order(names(st) %in% S)]),
      run(st[sample(n)])))
```

Output (fgsea 1.38.0 and 1.39.4, R 4.3.3; no warning is printed):

```
             order         ES       NES         pval
            <char>      <num>     <num>        <num>
1:        as given  0.5515578  1.813465 1.583640e-05
2: set moved first  0.6520603  2.143906 1.391070e-09
3:  set moved last -0.6444221 -2.111765 2.613403e-09
4:        shuffled  0.3574372  1.169329 1.232323e-01
```

The same 100 genes, with the same statistics, come out at p = 1e-9 in either direction or at p = 0.12, depending only on the order of the input vector. In a run with 200 random 100-gene pathways on the same list the set "as given" gets padj 1.5e-3, while the smallest padj among the random sets is 0.28. 1.30.0 and 1.36.2 give the same numbers.

How often this happens with standard collections is another matter. We could not find an MSigDB set of 15 or more genes that is entirely at 0 on real bulk and single-cell lists. A custom set of genes that are not expressed in the data would hit it, though.

### Possible changes (your call)

1. Warn when a tested pathway has total weight 0, e.g. "N pathways contain only genes with zero statistic; their ES depends on the order of tied genes", or
2. include zeros in the existing ties warning when such a pathway is tested, or
3. return `NA` for such pathways, as for the unbalanced case.

I'm happy to send a PR for whichever you prefer.
