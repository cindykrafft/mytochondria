`tests/testthat/test_gsea_multilevel.R`, test "fgseaMultilevel is reproducable independent of bpparam settings", runs `fgseaMultilevel()` four times with `set.seed(42)` and different `nproc` values and checks

```r
expect_equal(fr1$nMoreExtreme, fr$nMoreExtreme)
```

`fgseaMultilevel()` drops `nMoreExtreme` from its result (`result[, nMoreExtreme := NULL]`), so all three expectations compare `NULL` with `NULL` and pass whatever the p-values are:

```r
> set.seed(42); fr <- fgseaMultilevel(examplePathways[1:2], exampleRanks, sampleSize = 50, maxSize = 500, nproc = 1)
> names(fr)
[1] "pathway"     "pval"        "padj"        "log2err"     "ES"         
[6] "NES"         "size"        "leadingEdge"
> is.null(fr$nMoreExtreme)
[1] TRUE
```

If the `nproc = 2` call in that test is seeded with 43 instead of 42, the test still passes (3 expectations, 0 failures). Comparing `pval` and `NES` instead makes it fail in that case (2 failures). With the seeds as they are, it passes on current master: the results are identical for `SerialParam()`, `nproc = 1, 2, 4`, the default `bpparam()` and `SnowParam(2)`.

A related small thing in `setUpBPPARAM()`: for `nproc == 1` it assigns `SerialParam(progressbar = TRUE)` and then, in the next `if`, overwrites it with `MulticoreParam(workers = 1)` (or `SnowParam` on Windows), so `nproc = 1` still forks a worker:

```r
> class(fgsea:::setUpBPPARAM(nproc = 1))[1]
[1] "MulticoreParam"
```

Results are the same either way, because the seeds are drawn before `bplapply()`.

I have both as two small commits (the test comparing `pval`/`NES`, and an `else if` in `setUpBPPARAM()`). With them, the package's 61 tests pass. Happy to open the PR if that's useful.
