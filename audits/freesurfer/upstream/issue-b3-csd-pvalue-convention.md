Title: CSD p-values use nover/nreps with strict '>' rather than the exact
permutation convention; env-var fix is not the default

**Summary.** `CSDpvalClustSize` (utils/volcluster.cpp) computes empirical
cluster p-values as `nover/nreps` counting only simulations with a strictly
larger max cluster; the exact convention p = (b+1)/(m+1) with >= (Phipson &
Smyth 2010) exists behind the env var `FS_CSDPVALCLUSTSIZE_GTE` (since
~7.2) but is off by default. The in-code comment itself says "Using just >
is too liberal". `CSDpvalMaxSig` has the same convention and additionally
no floor, so a voxel that beats all simulations receives p = 0 and
`CSDpvalMaxSigMap` writes -log10(0) = inf into sig.voxel.mgh.

**Empirical note:** in a Monte Carlo with heavily tied small cluster sizes
(CDT z=3.1, FWHM 1.5 voxels, 5,000 sims), the strict-'>' convention alone
inflated a *matched-connectivity* cluster correction to achieved FWER 0.129
at nominal 0.05. With realistic nsim (1,000-10,000) the effect on smooth
data is bounded by ~1/nsim but concentrates exactly at borderline p.

**Ask:** make the exact convention the default (or at least for --perm,
where exactness is the point), floor CSDpvalMaxSig at 1/nreps, and document
the change since it can move p=0.049 to p=0.051.
