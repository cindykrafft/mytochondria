The one-voxel shift comes from `mri_convert` building its output template by copying the input header and then only rewriting the direction cosines for `--out_orientation` (or `--out_{i,j,k}_direction`), leaving `c_ras` untouched — but `c_ras` is the RAS position of voxel (W/2, H/2, D/2), which for even dimensions sits half a voxel off the true FOV center, so flipping an axis while keeping it moves the whole grid by one voxel along that axis (hence the plane of zeros at index 0 and the slice lost on the way back). The fix records the physical FOV center before the cosines change and re-derives `c_ras` from it afterwards, which is exactly what `MRIreorder()` already does, so `--out_orientation LIA` now matches `--reorder -1 3 -2` voxel-for-voxel and the LIA→RAS round trip restores the input.
