Title: bf: mri_convert --out_orientation keeps the field of view fixed (one-voxel shift on flipped axes)

Fixes #1358.

**What was wrong.** `mri_convert` builds its output template by copying the input header and, for `--out_orientation` (and `--out_{i,j,k}_direction`), rewrites only the direction cosines, leaving `c_ras` unchanged. `c_ras` is the RAS coordinate of voxel (W/2, H/2, D/2), which for even dimensions is half a voxel away from the true center of the field of view at ((W-1)/2, (H-1)/2, (D-1)/2). Keeping it fixed while an axis is flipped therefore moves the whole output grid by one voxel along that axis: the first slice of every flipped axis samples outside the input (a plane of zeros, 65,536 voxels per axis on a 256³ volume), and reorienting back loses a slice on each of those axes. As reported, `--out_orientation LIA` and `--reorder -1 3 -2` gave different `c_ras` (128 vs 127) and different data.

**The fix** (`mri_convert/mri_convert.cpp`). Before the cosines are changed, remember the RAS position of the FOV center (`vox2ras * ((W-1)/2, (H-1)/2, (D-1)/2)`); after they are changed, re-derive `c_ras = FOVcenter + Mdc * D * (1/2, 1/2, 1/2)` with the new cosines. This is the same invariant `MRIreorder()`/`MRIreorderVox2RAS()` already maintain. It only runs when `--out_orientation` or `--out_{i,j,k}_direction` is given; `--out_center` still overrides afterwards, and every other path is byte-identical. Note this intentionally changes the output of the affected invocations by the one-voxel shift being fixed.

**Test.** `mri_convert/test.sh` gains a check on the existing `indata/ref/rawavg-conform.ref.mgz`: `--out_orientation RAS -rt nearest` must equal `--reorder -1 -3 2` (`compare_vol`), and reorienting that back to LIA must reproduce the reference exactly. Both comparisons fail before the change and pass after it. I could not run `test.sh` itself here (`testdata.tar.gz` is a git-annex object), so the same two comparisons were run on a synthetic conformed LIA volume with random uchar data, plus the reporter's 256³ volume of ones:

| check | before | after |
|---|---|---|
| zeros in `ones_LIA.mgz` (`--out_orientation LIA`) | 130,816 | 0 |
| zeros in `ones_RAS.mgz` (LIA back to RAS) | 130,816 | 0 |
| `mri_diff ones_LIA.mgz ones_reorder.mgz` | geometry + data differ | identical |
| `mri_diff` synthetic conformed: `--out_orientation RAS` vs `--reorder -1 -3 2` | differ | identical |
| `mri_diff` synthetic conformed: round trip vs input | differ | identical |

Unaffected invocations are unchanged (`mri_diff` before vs after: plain copy, `--conform`, `-vs 2 2 2`, `--out_center`, and `--out_orientation` with `--out_center` all give `diffcount 0` and identical geometry).
