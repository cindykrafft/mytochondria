Title: A Phred+33 file whose lowest quality is 31 or more is reported as Illumina 1.5 and every quality is shifted down by 31 (follow-up to #147, with a proposed default)

**Versions:** 0.11.5, 0.11.9, 0.12.1 and `master` @ 87fb336, same behaviour.

`PhredEncoding.getFastQEncodingOffset(char lowestChar)` decides the encoding from the lowest quality character in the file: below `'@'` (64) is "Sanger / Illumina 1.9" (offset 33), `'@'` and above is Illumina 1.3/1.5 (offset 64). A Phred+33 file in which no base has a quality below 31 (`'@'`) is therefore read with offset 64: Q37 (`'F'`) becomes 6, Q31 becomes 0, the Basic Statistics line says `Encoding Illumina 1.5`, and the per-base and per-sequence quality modules and their pass/warn/fail flags follow. #147 reported this on a NextSeq 2000 run in which every base was `'C'` (Q34); the reply there was that such a file "would be a fairly remarkable dataset unless it's been heavily filtered", and the issue was closed without a change. This is a follow-up with a reproduction and a proposal, because heavily filtered files are now routine: the two-colour instruments emit four binned qualities (2, 12, 23, 37), and any filter that drops reads or trims bases below Q30 (fastp `-q 30`, Trimmomatic `SLIDINGWINDOW:4:30` plus `MINLEN`, or a Q30 read filter) leaves files whose lowest quality is 37. #210 removes the guess for BAM/SAM input; FASTQ input still guesses.

**Reproduction** (500 reads of 50 bp, qualities drawn from {31, 33, 36, 37}, written as Phred+33):

```
Encoding                       Illumina 1.5
Per base sequence quality      mean at position 1: 3.22  (true mean 34.3)
```

and the same file with a single Q30 base added anywhere is read correctly. Script: `f1_basic_quality_modules.py` (library C) in the repository linked below.

The module page acknowledges the guess can be wrong "only when your data is universally very good".

**Proposal.** No instrument has produced Illumina 1.3/1.5 (offset 64) data since 2011, whereas Phred+33 files whose lowest character is in `'@'`–`'J'` are the common case today. Either (a) default to offset 33 unless a character above `'J'` (74, Q41 in Phred+33; Q10 in Illumina 1.5) is present, since a genuine Illumina 1.5 file with nothing above Q10 is hard to imagine, or (b) add an `--encoding`/`--phred33` option so pipelines can state it. Happy to send a PR for (a), (b) or both.
