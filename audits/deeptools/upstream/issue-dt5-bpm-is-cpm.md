Title: bamCoverage --normalizeUsing BPM produces the CPM track, not the documented "reads per bin / sum of all reads per bin"

**What happens.** The `--normalizeUsing` help defines "BPM (per bin) = number of reads per bin / sum of all reads per bin (in millions)" and "BPM = Bins Per Million mapped reads, same as TPM in RNA-seq". `getScaleFactor.get_scale_factor` (`deeptools/getScaleFactor.py`, lines 284-292) computes

```python
tile_len_in_kb = float(args.binSize) / 1000
tpm_scaleFactor = (bam_mapped / tile_len_in_kb) / 1e6
scale_factor *= 1 / (tpm_scaleFactor * tile_len_in_kb)
```

which simplifies to `1e6 / bam_mapped`, the CPM factor of lines 278-279; the commented-out `# sampled_bins_sum = getSampledSum(args.bam)` on line 288 is what remains of the documented denominator (commit 2fbfaf26, "implmented BPM norm, not tested for accuracy"). Since a read is counted in every bin it overlaps, the sum of all reads per bin exceeds the number of mapped reads by the mean number of bins a read touches (about 3 for 100-bp reads in 50-bp bins, about 7 with `--extendReads 300`), so the emitted BPM values are that factor larger than the documented ones, and their sum over the genome is not 1e6.

**Minimal reproduction** (5,000 100-bp reads on a 100-kb chromosome, 50-bp bins):

```python
import subprocess, numpy as np, pysam, pyBigWig

L = 100000
with pysam.AlignmentFile("/tmp/c.u", "wb", header={"HD": {"VN": "1.0"}, "SQ": [{"SN": "chr1", "LN": L}]}) as fh:
    for i, s in enumerate(np.random.RandomState(0).randint(0, L - 100, 5000)):
        a = pysam.AlignedSegment(); a.query_name = "r%d" % i; a.query_sequence = "A" * 100; a.flag = 0
        a.reference_id = 0; a.reference_start = int(s); a.mapping_quality = 30; a.cigar = ((0, 100),)
        a.query_qualities = pysam.qualitystring_to_array("I" * 100); fh.write(a)
pysam.sort("-o", "/tmp/c.bam", "/tmp/c.u"); pysam.index("/tmp/c.bam")
tracks = {}
for norm in ["CPM", "BPM"]:
    subprocess.run(["bamCoverage", "-b", "/tmp/c.bam", "-o", "/tmp/%s.bw" % norm, "-bs", "50", "--normalizeUsing", norm], check=True, capture_output=True)
    tracks[norm] = np.array(pyBigWig.open("/tmp/%s.bw" % norm).values("chr1", 0, L))[::50]
print("BPM == CPM bit for bit:", np.array_equal(tracks["CPM"], tracks["BPM"]))
print("sum of BPM over all bins: %.0f (documented definition gives 1e6)" % np.nansum(tracks["BPM"]))
assert not np.array_equal(tracks["CPM"], tracks["BPM"]), "BPM and CPM produced the same track"
```

**Possible fixes.** Either implement the documented denominator (the sum of the per-bin counts, which needs one pass over the genome, or the sampled estimate the commented-out `getSampledSum` was meant to give), or document that BPM is computed as reads per bin / mapped reads (in millions) and equals CPM.
