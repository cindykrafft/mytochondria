Title: plotFingerprint: a fragment ending inside a bin credits that bin with a whole tile when the sampling step equals --binSize

**What happens.** `SumCoveragePerBin.get_coverage_of_region` (`deeptools/sumCoveragePerBin.py`, lines 169-199) computes `eIdx` as the *ceiling* bin of the fragment end and then

```python
_ = sIdx + 1
while _ < eIdx:
    coverages[_] += tileSize
    _ += 1
...
if eIdx > sIdx:
    _ = fragmentEnd - (reg[0] + eIdx * tileSize)   # <= 0 by construction
    ...
    coverages[eIdx] += _                           # clamped to 0
```

so every bin up to and including the bin the fragment ends in receives a full tile, and the branch written for the partial last bin adds `max(0, negative)`. This is the code path for a multi-bin region, which `countReadsPerBin.count_reads_in_region` uses when the sampling step equals the bin length (`stepSize == self.binLength`, one `(start, end, binLength)` region per chunk): `--numberOfSamples` equal to the genome length divided by `--binSize`, or a `--region` with that ratio. With the default `-n 500000` the step differs from the bin size, each bin is its own two-tuple region and the sums are exact; the plot and the `--outQualityMetrics` are only wrong on the multi-bin path.

**Minimal reproduction** (one 50-bp read at 50-100, 40-bp bins over 0-200: per-base sums are 30 in bin 40-80 and 20 in bin 80-120):

```python
import numpy as np, pysam
from deeptools.sumCoveragePerBin import SumCoveragePerBin

with pysam.AlignmentFile("/tmp/f.u", "wb", header={"HD": {"VN": "1.0"}, "SQ": [{"SN": "chr1", "LN": 200}]}) as fh:
    a = pysam.AlignedSegment(); a.query_name = "r"; a.query_sequence = "A" * 50; a.flag = 0
    a.reference_id = 0; a.reference_start = 50; a.mapping_quality = 30; a.cigar = ((0, 50),)
    a.query_qualities = pysam.qualitystring_to_array("I" * 50); fh.write(a)
pysam.sort("-o", "/tmp/f.bam", "/tmp/f.u"); pysam.index("/tmp/f.bam")
c = SumCoveragePerBin([], stepSize=40, binLength=40)
got = c.get_coverage_of_region(pysam.AlignmentFile("/tmp/f.bam"), "chr1", [(0, 200, 40)])
print("bin sums:", got.tolist(), " expected: [0, 30, 20, 0, 0]")
np.testing.assert_equal(got, [0, 30, 20, 0, 0])
```

Through the command line on a 500-kb genome with 500-bp bins and 50-bp reads, `-n 1000` (step 500) over-counts 560 of 1,000 bins by 1,678 on average and the reported total is 1.94 times the true per-base sum, while `-n 2000` (step 250) is exact.

**Fix.** Replace the three-part bookkeeping by the per-bin overlap `min(fragmentEnd, binEnd) - max(fragmentStart, binStart)`; a patch with a test on `testB.bam` (expected sums `[0, 30, 40, 50, 80]` with 40-bp bins) is ready and a PR follows.
