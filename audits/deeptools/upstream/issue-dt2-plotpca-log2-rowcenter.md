Title: plotPCA: --log2 has no effect on the PCA, and --rowCenter none unless --ntop 0

**What happens.** `Correlation.plot_pca` (`deeptools/correlation.py`, lines 606-629) does

```python
m = self.matrix
...
if self.ntop > 0 and m.shape[0] > self.ntop:
    m = m[np.argpartition(rvs, -self.ntop)[-self.ntop:], :]   # m is now a copy
if self.log2:
    self.matrix = np.log2(self.matrix + 0.01)                   # rebinds self.matrix; m unchanged
if self.rowCenter and not self.transpose:
    _ = self.matrix.mean(axis=1)
    self.matrix -= _[:, None]                                   # in place on self.matrix
if self.transpose:
    m = m.T
m2 = (m - np.mean(m, axis=0))                                    # the SVD input is m
```

so `--log2` never reaches the matrix the SVD is computed from, and `--rowCenter` only does when `m` is still the same object as `self.matrix` (no `--ntop` selection, i.e. `--ntop 0` or fewer rows than `--ntop`) and `--log2` is not given. With the default `--ntop 1000` any genome-wide multiBamSummary/multiBigwigSummary matrix is copied, so both options are silently ignored. (A side effect of the same lines: `--rowCenter` on an integer-valued matrix aborts with `UFuncOutputCastingError` from the in-place subtraction.)

**Minimal reproduction** (a multiBamSummary-style matrix with a strong per-bin baseline, so that log2 must change the loadings; shrinking showed the data do not matter, any matrix with more than `--ntop` rows reproduces it):

```python
import subprocess, numpy as np

rng = np.random.RandomState(0)
mat = rng.poisson(rng.gamma(2.0, 50.0, 3000)[:, None] * np.array([1.0, 1.5, 0.5, 2.0])).astype(float)
with open("/tmp/m.npz", "wb") as fh:
    np.savez_compressed(fh, matrix=mat, labels=["a", "b", "c", "d"])

def loadings(extra):
    subprocess.run(["plotPCA", "-in", "/tmp/m.npz", "--outFileNameData", "/tmp/pca.tab"] + extra, check=True)
    return [line.split("\t")[1:5] for line in open("/tmp/pca.tab") if line[0].isdigit()]

plain, log2, rc = loadings([]), loadings(["--log2"]), loadings(["--rowCenter"])
print("PC1 loadings, no option :", plain[0])
print("PC1 loadings, --log2    :", log2[0])
print("PC1 loadings, --rowCenter:", rc[0])
assert log2 != plain, "--log2 had no effect on the PCA"
```

Expected: different loadings with `--log2` (a numpy implementation of the documented pipeline — top-N rows, log2(x + 0.01), column centring and scaling with ddof 1, SVD — gives PC1 `[0.5022 0.4981 0.5013 0.4985]` on the project's 4,000-bin example versus `[0.4981 0.4974 0.5019 0.5026]` without log2). The default and `--transpose` results do match that reference, so only the two options are affected.

**Fix.** Apply the log2 transform and the row centring to `m`; a patch with a test against the numpy reference (all four option combinations) is ready and a PR follows.
