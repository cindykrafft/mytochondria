Title: [comment for #1108 / #1130] bamCompare --skipZeroOverZero: cause of the coordinate shift and a fix

- [x] deepTools version: 3.5.6 (`master` @ `ea0f68bb`, also reproduced on 3.5.1 and 3.3.1); Python 3.12.3
- [x] Full command producing the issue: see the script below (`bamCompare -b1 a.bam -b2 b.bam -o out.bg -of bedgraph -bs 100 --scaleFactors 1:1 --operation first --skipZeroOverZero`)
- [x] Output printed: see below

**Cause.** `writeBedGraph.WriteBedGraph.writeBedGraph_worker` (`deeptools/writeBedGraph.py`, lines 246-274) run-length-encodes the bin values and takes the coordinates of every new interval from the previous interval's `writeEnd`. The skipped bin

```python
if self.skipZeroOverZero and np.sum(tileCoverage) == 0:
    continue
```

neither advances `writeEnd` nor resets `previous_value`, so the next written bin starts where the skipped bin started and every later interval in the chunk is one bin too far left; when the value after the gap equals the value before it, the gap is merged into the run and written with that value. The bigWig-input version of the same loop (`writeBedGraph_bam_and_bw.py`, line 100-102, used by bigwigCompare) resets `previousValue = None` on the skip and does not have the problem. `test_bam_compare_ZoverZ` only has a leading zero bin, which the `previous_value is None` branch handles, so the existing test passes.

**Minimal reproduction** (one 500-bp chromosome, 100-bp bins, reads only in bins 0 and 2; shrinking showed that a single interior zero-over-zero bin is enough and that `--operation` does not matter):

```python
import subprocess, pysam

def bam(path, starts):
    with pysam.AlignmentFile(path + ".u", "wb", header={"HD": {"VN": "1.0"}, "SQ": [{"SN": "chr1", "LN": 500}]}) as fh:
        for i, s in enumerate(starts):
            a = pysam.AlignedSegment(); a.query_name = "r%d" % i; a.query_sequence = "A" * 50; a.flag = 0
            a.reference_id = 0; a.reference_start = s; a.mapping_quality = 30; a.cigar = ((0, 50),)
            a.query_qualities = pysam.qualitystring_to_array("I" * 50); fh.write(a)
    pysam.sort("-o", path, path + ".u"); pysam.index(path)

bam("/tmp/a.bam", [10, 20, 220]); bam("/tmp/b.bam", [10, 220])
subprocess.run(["bamCompare", "-b1", "/tmp/a.bam", "-b2", "/tmp/b.bam", "-o", "/tmp/out.bg", "-of", "bedgraph",
                "-bs", "100", "--scaleFactors", "1:1", "--operation", "first", "--skipZeroOverZero"], check=True, capture_output=True)
got = open("/tmp/out.bg").read()
print("got:\n" + got)
expected = "chr1\t0\t100\t2\nchr1\t200\t300\t1\n"
assert got == expected, "expected:\n" + expected
```

**Output** (3.5.6):

```
got:
chr1	0	100	2
chr1	100	500	1

AssertionError: expected:
chr1	0	100	2
```

Bin 2's value is written at bin 1's coordinates and stretched over the two skipped bins that follow it. On a 20-kb test genome with 50-bp bins and 206 of 400 bins empty in both files, 375 of the 400 bins carry a wrong value with `--skipZeroOverZero` (0 without).

**Fix.** Flush the current run and set `previous_value = None` on the skip, as `writeBedGraph_bam_and_bw.py` does; a patch with a regression test (an interior zero bin on `test_filtering.bam`, compared with the bamCoverage track of the same file) is ready and a PR follows.
