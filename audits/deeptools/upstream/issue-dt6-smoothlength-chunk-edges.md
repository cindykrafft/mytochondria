Title: bamCoverage/bamCompare --smoothLength: windows are truncated at every multiprocessing chunk boundary, not only at chromosome ends

- [x] Search whether this issue (or a similar issue) has been solved before: no prior report found (nearest: #99, bigWig size with smoothing; #1144, variable bin sizes).
- [x] deepTools version: 3.5.6 (`master` @ `ea0f68bb`; also reproduced on 3.5.1 and 3.3.1); Python 3.12.3
- [x] Full command producing the issue: `bamCoverage -b s.bam -o s.bg -of bedgraph -bs 50 --smoothLength 250 --region chr1:0:2000000` (script below)
- [x] Output printed: see below

**What happens.** `WriteBedGraph.writeBedGraph_worker` (`deeptools/writeBedGraph.py`, lines 238-243) smooths within the coverage vector of its own chunk, `getSmoothRange(tileIndex, binLength, smoothLength, coverage.shape[0])`, so the bins within half a window of a chunk edge are averaged over a one-sided window. Chunk edges fall every `genomeChunkLength` bases — `min(5e6, 2e6 / (mapped reads per bp * files))` rounded to the bin size (`getGenomeChunkLength`), or at most every 1e6 bases with `--region` (`mapReduce.getUserRegion`) — so the smoothed values at those positions depend on how the genome was partitioned and differ from a sliding mean over the chromosome.

**Minimal reproduction** (40,000 50-bp reads on a 2-Mb chromosome; `--region` forces 1-Mb chunks; a 5-bin window; shrinking showed only the four bins around 1,000,000 differ):

```python
import subprocess, numpy as np, pysam

L = 2000000
rng = np.random.RandomState(0)
starts = rng.randint(0, L - 50, 40000)
with pysam.AlignmentFile("/tmp/s.u", "wb", header={"HD": {"VN": "1.0"}, "SQ": [{"SN": "chr1", "LN": L}]}) as fh:
    for i, s in enumerate(starts):
        a = pysam.AlignedSegment(); a.query_name = "r%d" % i; a.query_sequence = "A" * 50; a.flag = 0
        a.reference_id = 0; a.reference_start = int(s); a.mapping_quality = 30; a.cigar = ((0, 50),)
        a.query_qualities = pysam.qualitystring_to_array("I" * 50); fh.write(a)
pysam.sort("-o", "/tmp/s.bam", "/tmp/s.u"); pysam.index("/tmp/s.bam")
subprocess.run(["bamCoverage", "-b", "/tmp/s.bam", "-o", "/tmp/s.bg", "-of", "bedgraph", "-bs", "50", "--smoothLength", "250",
                "--region", "chr1:0:2000000"], check=True, capture_output=True)
got = np.zeros(L // 50)
for line in open("/tmp/s.bg"):
    c, s, e, v = line.split(); got[int(s) // 50:int(e) // 50] = float(v)
counts = np.zeros(L // 50)
for s in starts:
    counts[s // 50:(s + 49) // 50 + 1] += 1
ref = np.array([counts[max(0, i - 2):i + 3].mean() for i in range(len(counts))])
bad = np.flatnonzero(~np.isclose(got, ref, atol=1e-6))
print("bins differing from the chromosome-wide 5-bin mean:", [int(b * 50) for b in bad])
assert len(bad) == 0, "smoothed values differ next to the chunk boundary at 1,000,000"
```

**Output** (3.5.6):

```
bins differing from the chromosome-wide 5-bin mean: [999900, 999950, 1000000, 1000050]
Traceback (most recent call last):
  File "mcve_dt6_smooth.py", line 27, in <module>
    assert len(bad) == 0, "smoothed values differ next to the chunk boundary at 1,000,000"
AssertionError: smoothed values differ next to the chunk boundary at 1,000,000
```

Every other bin equals the chromosome-wide window mean. On the project's 3-Mb example the bin at 1,000,000 is 1.3333 instead of 2.8000. Genome-wide runs on human-sized data at typical depth have a 5-Mb chunk, so about 600 boundaries carry (window − 1) one-sided bins each; it is a small effect, but it is one that makes the output depend on the chunking and on `--region`.

**Possible fix.** Count reads for `smoothLength / 2` beyond each chunk edge (the fetch already extends by the fragment length for `--extendReads`) and drop the margin after smoothing. I have not prepared a patch.
