### PR 1 — `fix4/bamcompare-skipzerooverzero-gap` — "bamCompare: do not collapse across a bin skipped by --skipZeroOverZero"

- [ ] Does the PR contain new feature? No
- [x] Does the PR contain bugfix? Yes — fixes #1108 and #1130 on the 4.0.0 tree
- [x] Does the PR contain documentation changes? A `CHANGES.txt` bullet only
- [ ] Does the PR contain changes to the galaxy wrapper? No

The 4.0.0 backend no longer shifts coordinates after a `--skipZeroOverZero` bin (each bin keeps its own start/end through `r_bamcompare`), but the default run-length collapse (`itertools::coalesce` in `src/bamcompare.rs`) merges neighbouring intervals whenever their values and chromosome agree, without checking that they touch. A bin removed by `--skipZeroOverZero` (or `--skipNonCoveredRegions`) between two bins of the same value was therefore bridged and written with that value — the second symptom in #1108/#1130. `--no_collapse` was unaffected. This adds `p.1.end == c.1.start` to the merge condition.

Test: `test_bam_compare_ZoverZ_interior_bins` compares `test_filtering.bam` with itself (`--operation subtract`, 0 everywhere) with 10-bp bins over `3R:0-200`; the zero-over-zero bin 60-70 must split the run into `0-60` and `70-200` (unmodified `master` writes a single `3R 0 200 0`). Fails on `master`, passes with the patch; `cargo test` 48 passed; `test_bamCoverage_and_bamCompare.py` and the full pytest suite pass (numbers in `test-runs.txt`).

### PR 3 — `fix4/plotcorrelation-mad-outliers` — "plotCorrelation: use the median absolute deviation in --removeOutliers"

- [ ] Does the PR contain new feature? No
- [x] Does the PR contain bugfix? Yes — fixes #NNN
- [x] Does the PR contain documentation changes? A `CHANGES.txt` bullet only
- [ ] Does the PR contain changes to the galaxy wrapper? No

`Correlation.get_outlier_indices` scaled the deviation from the median by `1.4826 * median(|x|)` — the median itself for counts — instead of `median(|x - median|)`, the MAD its docstring and the `--removeOutliers` help name. Bins were only flagged beyond ~300× the median, so the option removed nothing on count matrices. One line. **Behaviour change to flag in review:** `--removeOutliers` will now actually remove bins that are more than 200 MADs from the median in every sample, so Pearson values change for data with such bins (that is the option's purpose); the default (no option) is unchanged.

Test: `test_plotcorrelation.py::test_get_outlier_indices_uses_median_absolute_deviation` (three planted bins at 50× the median among 5,000 Poisson(100) bins are flagged, none on clean data); fails on `master`, passes with the patch; `test_plotcorrelation.py` + `test_plotPCA.py` and the full suite pass; `correlation.py` doctests pass.

### PR 4 — `fix4/multibigwigsummary-exact-stats` — "multiBigwigSummary: compute bin means from the exact bigWig values"

- [ ] Does the PR contain new feature? No
- [x] Does the PR contain bugfix? Yes — fixes #NNN
- [x] Does the PR contain documentation changes? A `CHANGES.txt` bullet only
- [ ] Does the PR contain changes to the galaxy wrapper? No

`countFragmentsInRegions_worker` calls pyBigWig's `stats()` with the default `exact=False`, which answers from the zoom level whose reduction span fits the region. On the bigWigs bamCoverage writes those summaries are not the mean of the values inside the bin. With the 4.0.0 writer (bigtools; zoom spans 640 and 2560 bp on a 2-Mb test track) this is now worse than on 3.5.6: every bin or BED region of 1280 bp or more is answered from a zoom level, the default 10-kb bins deviate from the exact mean by a median of 1.4 % and up to 156 % next to peaks, 2-kb bins by up to 263 %, and peak-sized BED regions above 1.3 kb are affected too (on 3.5.6 the threshold was ~1.9 kb). `exact=True` reads the intervals themselves, as computeMatrix, bigwigCompare and bigwigAverage already do. **Behaviour change to flag in review:** every multiBigwigSummary value can change; the expected numbers of the existing `test_multiBigwigSummary_gtf` were themselves zoom summaries (27.3125 for the second transcript; the exact mean of its bases is 27.8067) and are updated in this PR. Runtime: the exact path is slower on large bins; if that matters, an `--exact` switch defaulting to on would keep the old speed available.

Test: `test_multiBigwigSummary_bins_exact_mean` writes a 400-kb track with 50-bp steps and a peak next to a bin boundary and compares the 10-kb bin means with numpy; it and the updated `test_multiBigwigSummary_gtf` fail on `master` (2 failed), pass with the patch; `test_bigwigCompare_and_multiBigwigSummary.py` 8 passed, full suite 233 passed; `getScorePerBigWigBin.py` doctests pass.

`SumCoveragePerBin.get_coverage_of_region` (unchanged from 3.5.6; plotFingerprint is still the Python implementation in 4.0.0) added a whole tile to every bin up to the ceiling bin of the fragment end, so a fragment ending inside a bin credited that bin with the full tile and the branch for the partial last bin only ever added `max(0, negative)`.
