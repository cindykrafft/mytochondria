**Cause.** `src/normalization.rs`, lines 30-35 (`scale_factor`, `"BPM"` arm), carried over verbatim from `getScaleFactor.py:284-292`:

```rust
"BPM" => {
    // BPM = bins per million mapped reads
    let bs_kb: f32 = binsize as f32 / 1000.0;
    let tmp_scalefactor = (mapped as f32 / bs_kb) / 1e6;
    scale_factor *= 1.0 / (tmp_scalefactor * bs_kb);
}
```

which is `1e6 / mapped`, the `"CPM"` arm three lines above. The `--normalizeUsing` help (`pydeeptools/deeptools/parserCommon.py:243-244`) defines "BPM (per bin) = number of reads per bin / sum of all reads per bin (in millions)" and "same as TPM in RNA-seq". A read is counted in every bin it overlaps (`src/covcalc.rs`, `bam_pileup`, lines 457-485), so the sum of all reads per bin is the number of mapped reads times the mean number of bins a read touches, and the documented values sum to 1e6 over the genome.

**Minimal reproduction** (`../upstream/mcve_dt5_bpm.py`, unchanged: 20,000 single-end 100-bp reads on a 300-kb chromosome, 50-bp bins; the CPM and BPM bigWigs are compared bit for bit and the BPM track is summed):

**Output** (4.0.0, `../verify/dt5_bpm_equals_cpm.v4.0.0.out`):

```
100-bp reads, no extension: mapped reads 20000, sum of reads per bin 59613 (2.98 bins per read)
  CPM track equals closed-form CPM: True (max |diff| 0)
  BPM track identical to CPM track: True (max |diff| 0); sum of BPM track over bins = 2980650 (documented: 1e6)
  emitted BPM / documented BPM = 2.981 on every covered bin (min 2.981, max 2.981)
--extendReads 300: ...
  BPM track identical to CPM track: True (max |diff| 0); sum of BPM track over bins = 6978500 (documented: 1e6)
  emitted BPM / documented BPM = 6.979 on every covered bin (min 6.978, max 6.979)
```

The numbers are the same as on 3.5.6 (`../verify/dt5_bpm_equals_cpm.out`).

**Two possible fixes**, your call: (a) make BPM what the help says — the Rust pileup already has every bin count in hand, so `scale_factor` could take the sum of all bin counts (over the non-ignored chromosomes) and use `1e6 / sum`; or (b) change the help text to say that BPM is the CPM factor (and drop the "same as TPM" clause). I have not prepared a patch because either changes what users get or what they are told, and that is a maintainers' decision.
