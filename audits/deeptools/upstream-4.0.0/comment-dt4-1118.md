- [x] deepTools version: 4.0.0 (`master` @ `4db9d816`, Rust backend built with maturin; also reproduced on 3.5.6, 3.5.1 and 3.3.1); Python 3.12.3
- [x] Full command producing the issue: `bamCoverage -b pair.bam -o out.bg -of bedgraph --MNase -bs 1` (script below)

**Cause on 4.0.0.** `src/filtering.rs`, `Alignmentfilters::manipulate_record`, lines 293-300:

```rust
let recpos: u32 = rec.pos() as u32;
let frag_start = recpos - 1 + rinsertsize / 2;

if rinsertsize % 2 == 0 {
    return Some((frag_start..frag_start + 2).collect());
} else {
    return Some((frag_start..frag_start + 4).collect());
}
```

For an odd template length 2k+1 the fragment `[pos, pos+2k+1)` has its centre at `pos+k`; `frag_start = pos - 1 + k`, and the range of four covers `pos+k-1 .. pos+k+2`, i.e. the centre, one base to its left and two to its right. The help says "Only 3 nucleotides at the center of each fragment are counted". The Python implementation (`bamCoverage.py`, still shipped as `bamCoverage_old`) gets the same four bases through `read.tlen / 2` being true division; the Rust port made the four explicit.

**Minimal reproduction** (one proper pair, fragment 100-249, i.e. TLEN 149; documented centre bases 173, 174, 175):

```python
import subprocess, pysam

with pysam.AlignmentFile("/tmp/pair.u", "wb", header={"HD": {"VN": "1.0"}, "SQ": [{"SN": "chr1", "LN": 1000}]}) as fh:
    for pos, flag, tlen in [(100, 99, 149), (199, 147, -149)]:
        a = pysam.AlignedSegment(); a.query_name = "p"; a.query_sequence = "A" * 50; a.flag = flag
        a.reference_id = 0; a.reference_start = pos; a.mapping_quality = 30; a.cigar = ((0, 50),)
        a.query_qualities = pysam.qualitystring_to_array("I" * 50)
        a.next_reference_id = 0; a.next_reference_start = 199 if pos == 100 else 100; a.template_length = tlen
        fh.write(a)
pysam.sort("-o", "/tmp/pair.bam", "/tmp/pair.u"); pysam.index("/tmp/pair.bam")
subprocess.run(["bamCoverage", "-b", "/tmp/pair.bam", "-o", "/tmp/out.bg", "-of", "bedgraph", "--MNase", "-bs", "1"], check=True, capture_output=True)
covered = [l.split()[1:3] for l in open("/tmp/out.bg") if not l.rstrip().endswith("\t0")]
print("covered interval(s):", covered)
assert covered == [["173", "176"]], "expected [['173', '176']] (three bases 173, 174, 175)"
```

**Output** (4.0.0):

```
covered interval(s): [['173', '177']]
AssertionError: expected [['173', '176']] (three bases 173, 174, 175)
```

Six fragments of lengths 149, 150, 151, 200, 131, 199 give the two central bases for the two even lengths and four bases for all four odd ones (`../verify/dt4_mnase_center.v4.0.0.out`, same as 3.5.6).

**Fix.** `frag_start + 3` (`../upstream-4.0.0/0002-*.patch`, with cargo tests on synthetic proper-pair records and a pytest on the shipped `test_paired2.bam`; both fail on `4db9d816`). PR follows.
