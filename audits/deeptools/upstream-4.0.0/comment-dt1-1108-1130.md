Title: [comment for #1108 / #1130] --skipZeroOverZero on 4.0.0: the coordinate shift is gone, the gap is still filled in when the neighbours are equal

- [x] deepTools version: 4.0.0 (`master` @ `4db9d816`, built with maturin, Rust backend); Python 3.12.3. The 3.5.6 coordinate shift (PyPI's current release) is described in my earlier comment.
- [x] Full command producing the issue: see the script below (`bamCompare -b1 a.bam -b2 a.bam -o out.bg -of bedgraph -bs 100 --scaleFactors 1:1 --skipZeroOverZero`)
- [x] Output printed: see below

**On 4.0.0 the shift itself is fixed**: `r_bamcompare` (`src/bamcompare.rs`) carries each bin's own coordinates through the pipeline and `--skipZeroOverZero` just drops the bin (line 352-353), so nothing moves — verified on a 20-kb test genome with 206 of 400 bins zero in both files (0 bins misplaced; `../verify/dt1_skipzerooverzero_coordinates.v4.0.0.out`).

**What remains** is the second symptom of #1108 (the skipped bin written as part of the run around it). The default collapse of equal neighbouring bins (`src/bamcompare.rs`, lines 380-394) merges two intervals whenever their values and chromosome agree, without checking that they touch:

```rust
Box::new(raw_lines.coalesce(|p, c| {
    if p.1.value == c.1.value && p.0 == c.0 {
        Ok((p.0, Value { start: p.1.start, end: c.1.end, value: p.1.value }))
```

so a bin removed by `--skipZeroOverZero` (or `--skipNonCoveredRegions`) between two bins of the same value is bridged and comes out with that value. `--no_collapse` output is correct.

**Minimal reproduction** (one 500-bp chromosome, 100-bp bins, a file compared with itself, so every covered bin is log2(1) = 0 and bin 100-200 is zero-over-zero):

```python
import subprocess, pysam

def bam(path, starts):
    with pysam.AlignmentFile(path + ".u", "wb", header={"HD": {"VN": "1.0"}, "SQ": [{"SN": "chr1", "LN": 500}]}) as fh:
        for i, s in enumerate(starts):
            a = pysam.AlignedSegment(); a.query_name = "r%d" % i; a.query_sequence = "A" * 50; a.flag = 0
            a.reference_id = 0; a.reference_start = s; a.mapping_quality = 30; a.cigar = ((0, 50),)
            a.query_qualities = pysam.qualitystring_to_array("I" * 50); fh.write(a)
    pysam.sort("-o", path, path + ".u"); pysam.index(path)

bam("/tmp/a.bam", [10, 220])   # one read in bin 0-100 and one in bin 200-300; bin 100-200 empty
subprocess.run(["bamCompare", "-b1", "/tmp/a.bam", "-b2", "/tmp/a.bam", "-o", "/tmp/out.bg", "-of", "bedgraph",
                "-bs", "100", "--scaleFactors", "1:1", "--skipZeroOverZero"], check=True, capture_output=True)
got = open("/tmp/out.bg").read()
print("got:\n" + got)
expected = "chr1\t0\t100\t0\nchr1\t200\t300\t0\n"
assert got == expected, "expected:\n" + expected
```

**Output** (4.0.0):

```
got:
chr1	0	300	0

AssertionError: expected:
chr1	0	100	0
chr1	200	300	0
```

The same happens with `--operation subtract` on the shipped `test_filtering.bam` compared with itself (10-bp bins over `3R:0-200`: `3R 0 200 0` instead of `3R 0 60 0` and `3R 70 200 0`, the gap being 60-70).

**Fix.** Require `p.1.end == c.1.start` in the coalesce closure (one condition; `../upstream-4.0.0/0001-*.patch`, with that `test_filtering.bam` case as a regression test that fails on `4db9d816`). PR follows.
