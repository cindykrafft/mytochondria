On the 4.0.0 tree (`4db9d816`) the Rust-backed `computeMatrix` reads gzipped BED files itself, so `computeMatrix reference-point -R peaks.bed.gz ...` now runs through with the default `--sortRegions keep`. The same `TypeError` is still raised by `computeMatrixOperations sort -R regions.bed.gz` (and by `computeMatrix_old`), because `sortMatrix()` → `loadBED()` iterates the binary handle that `deeptoolsintervals.openPossiblyCompressed()` returns as `bytes`; `loadGTF()` in the same file already decodes its lines. PR #NNN applies the `parse.py#L15` pattern to `loadBED()`, with a test on a gzipped copy of the existing `computeMatrixOperations.bed` that fails on `master`. Workaround meanwhile: gunzip the BED before `sort`.
