### PR 1 — `fix/strandless-transcript-strand` — "Fix strand handling for GTF features with undefined strand ('.')"

Fixes #NNN.

**Purpose: bug-fix.** A GTF exon line whose strand column is `.` gives the transcript and
the gene the strand code `0` (`GTF.cpp:138-143`), distinct from `1` (`+`) and `2` (`-`).
`Transcriptome_geneCountsAddAlign.cpp:32-36` handles code `0` explicitly — *"genes w/o
strand will accept reads from both strands"* — but the transcriptome-BAM and STARsolo
counting paths test only for code `1` and treat everything else, code `0` included, as
the minus strand. The result is two wrong outputs, both silent:

- `Aligned.toTranscriptome.out.bam` gives every record on such a transcript the opposite
  `0x10` flag to the one its POS implies, because `alignToTranscript()` transforms the
  coordinates only when the code is `2` while `quantAlign()` set the flag for anything
  that is not `1`. SEQ, which SAM requires on the reference forward strand, then does not
  match the transcript at the reported POS, and `RSEM --forward-prob` / salmon / eXpress
  in a stranded library type keep exactly the wrong reads.
- STARsolo with `--soloStrand Forward` rejects every read on such a gene, so `Gene`,
  `GeneFull` and `GeneFull_Ex50pAS` report zero counts for it in every cell.

**The change.** Six one-line conditions, in five files:

| file | before | after |
|---|---|---|
| `Transcriptome_quantAlign.cpp:107` | `trStr[tr1]==1 ? aG.Str : 1-aG.Str` | `trStr[tr1]==2 ? 1-aG.Str : aG.Str` |
| `Transcriptome_classifyAlign.cpp:208` | strand test for any `trStr` | test skipped when `trStr[tr1]==0` |
| `Transcriptome_geneFullAlignOverlap.cpp:24`, `:43` | `geneFull.str[gi1]==1 ? a.Str : 1-a.Str` | `==2 ? 1-a.Str : a.Str`, and the gene accepts either strand when `str[gi1]==0` |
| `Transcriptome_geneFullAlignOverlap_ExonOverIntron.cpp:30` | same | same |
| `Transcriptome_alignExonOverlap.cpp:58` | `… == (trStr[tr1]-1)`, which is `-1` for code 0 | code 0 accepts both strands |

For codes `1` and `2` every expression is unchanged, so `+`/`-` annotations behave
exactly as before.

**Expected change in behaviour.** Only for annotations containing `.` in the strand
column: such transcripts are treated as `+` in the transcriptome BAM (matching the
coordinate transform that was already being applied), and such genes accept reads from
both strands in STARsolo — the same rule `--quantMode GeneCounts` has always used.
Genomic alignment, `SJ.out.tab`, `ReadsPerGene.out.tab` and `Log.final.out` are
untouched.

**Tests.** `extras/tests/scripts/testStrandlessTranscript.sh` (new) builds a 6-kb genome
with one two-exon transcript and maps the same reads against two GTFs that differ only in
the strand column, requiring the transcriptome records and the STARsolo counts to be
identical. On unpatched 2.7.11b it reports two failures — transcriptome FLAGs `0`/`16`
swapped, and `Gene`/`GeneFull`/`GeneFull_Ex50pAS` counts of `4` with `+` against `0` with
`.` — and exits 1; with this change it prints two PASS lines and exits 0.
