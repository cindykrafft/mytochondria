**Title:** `--012`, `--plink`, `--hap-r2`, `--geno-r2` (every temporary-file output) abort with "buffer overflow detected" when built with a fortifying compiler

Built from source on Ubuntu 24.04 (`./autogen.sh && ./configure && make`, GCC 13.3, glibc 2.39, the default `CXXFLAGS=-g -O2`), `master` at 1f87a83 and the v0.1.16 and v0.1.13 tags all abort in every mode that writes through a temporary file, before writing any output:

```
$ vcftools --vcf test.vcf --out t --012
...
After filtering, kept 6 out of 6 Individuals
Writing 012 matrix files ... *** buffer overflow detected ***: terminated
Aborted (core dumped)

$ vcftools --vcf test.vcf --out t --hap-r2
...
Outputting Pairwise LD (phased bi-allelic only)
*** buffer overflow detected ***: terminated
```

Same for `--plink`, `--plink-tped`, `--geno-r2`, `--geno-chisq`, `--interchrom-hap-r2`, `--interchrom-geno-r2`, `--hap-r2-positions`, `--geno-r2-positions`, `--ldhat`, `--ldhat-geno`, `--ldhelmet`. Any VCF with genotypes reproduces it; the six-sample, five-site file below is enough.

**Cause.** Each of these writers builds the `mkstemp` template in a `std::string` and copies it into a stack array sized to the string's length, without room for the terminating NUL:

```cpp
string new_tmp = params.temp_dir+"/vcftools.XXXXXX";
char tmpname[new_tmp.size()];
strcpy(tmpname, new_tmp.c_str());
fd = mkstemp(tmpname);
```

(`variant_file_format_convert.cpp`: `output_as_plink`, `output_as_012_matrix`, `output_as_LDhat_phased`, `output_as_LDhat_unphased`, `output_as_LDhelmet`; `variant_file_output.cpp`: `output_haplotype_r2`, `output_genotype_r2`, `output_genotype_chisq`, `output_interchromosomal_genotype_r2`, `output_interchromosomal_haplotype_r2`, `output_haplotype_r2_of_SNP_list_vs_all_others`, `output_genotype_r2_of_SNP_list_vs_all_others`; 19 arrays in all, some functions have two or three.) `strcpy` writes the NUL one byte past the end of the array. Since GCC 12 / glibc 2.35 the fortified `strcpy` can check the size of a variable-length array at run time (`__builtin_dynamic_object_size`), and Ubuntu 24.04, Fedora and Debian 13 enable `_FORTIFY_SOURCE=3` by default whenever `-O` is on, so the overflow is caught and the process is killed. Builds with `_FORTIFY_SOURCE=2` (the Debian/Ubuntu package, bioconda) or without fortification run the same code and write the NUL over whatever follows the array, which happens not to be visible.

**Fix.** Size the arrays `new_tmp.size()+1`. A PR follows with that change at all 19 sites; with it every mode above runs on the fortified build and the outputs are unchanged on a non-fortified one.
