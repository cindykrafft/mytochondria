Title: `--max-missing-count` counts missing alleles, the manual says missing genotypes

The man page:

> `--max-missing-count <integer>`: Exclude sites with more than this number of missing genotypes over all individuals.

`filter_sites_by_allele_count` (`entry_filters.cpp`) compares the number of missing *chromosomes*:

```cpp
if ((N_chr-N_non_missing_chr) > max_missing_call_count)
    passed_filters = false;
```

For diploid data every missing genotype is two missing chromosomes, so the filter is twice as strict as documented. 30 diploid individuals, 1200 sites with 0–10 missing genotypes per site: `--max-missing-count 3` keeps 392 sites (those with at most one missing genotype), while 572 sites have at most three missing genotypes (`vcftools --vcf x.vcf --max-missing-count 3 --kept-sites --out x`; generator and recount in `verify/v3_filters.py` of the repository linked below). Same on master (1f87a83), v0.1.16, v0.1.13 and Ubuntu's 0.1.16-3.

#28 (2016) reached the same conclusion — "vcftools refers to the number of missing alleles and not the number of missing genotypes" — and was closed by its reporter without the manual changing.

Since `--max-missing` is defined on the proportion of data (chromosomes) and nine years of users have calibrated to the current behaviour, the smaller change is the manual. Suggested wording for `vcftools.1` (and the website copy):

```
.B --max-missing-count
.I <integer>
.RS 2
Exclude sites with more than this number of missing alleles (chromosomes) over all individuals; for diploid data a missing genotype counts twice.
.RE
```

I can open a PR with that man-page change, or with a change of the comparison to genotypes if that is preferred.
