Title: With the default `adjustSize`, artificial doublets get another pair's origin label, so `scDblFinder.mostLikelyOrigin` is mostly wrong

**Describe the bug**

When `clusters` are given, `getArtificialDoublets()` builds the cross-cluster doublets with `createDoublets(x, ca, clusters=clusters, adjustSize=adjustSize, ...)` and then attaches the origins by position (`oc <- c(oc, as.character(ca$orig.clusters))`). With `adjustSize > 0` (default 0.25) `createDoublets` sums the non-adjusted pairs first and appends the size-adjusted ones (`x1 <- cbind(x1, x2)`), so from the first adjusted pair on, column *i* is no longer pair *i*. About half of the cross-cluster artificial doublets therefore carry a label that names a different pair of clusters than the cells they were made from.

Downstream, `.evaluateKNN` derives every cell's `mostLikelyOrigin` from the labels of its artificial-doublet neighbours, so the annotation the vignette describes under "Doublet origins and enrichments" is wrong most of the time: on a simulated capture (five cell types, 3,218 cells, 218 doublets, clusters given) `scDblFinder.mostLikelyOrigin` is right for 24 % of the heterotypic doublets, and for 100 % once the column order is kept. The doublet calls do not depend on the origins (same simulation: identical calls, score correlation 0.999 between the two runs; the residual difference is `.filterUnrecognizableDoublets`, which uses the labels to decide which combinations to drop from training).

Two more effects of the same block: because `dbl.idx` is reassigned to the adjusted subset, the halving that follows is applied to `ceiling(halfSize × number of adjusted pairs)` doublets instead of `ceiling(halfSize × pairs)` (5 instead of 20 of 40 pairs at `halfSize=0.5`); and when exactly one pair is selected for adjustment (`length(wAd) > 1` guard; 4–5 pairs at `adjustSize=0.25`) that pair is dropped, after which the halving indexes past the end ("subscript out of bounds").

**MRE -- Minimal example to reproduce the bug**

Three well-separated clusters; each cross-cluster artificial doublet is compared with the three possible sums of cluster means and the best match is compared with its label:

```r
library(scDblFinder); library(SingleCellExperiment)
set.seed(1)
sce <- mockDoubletSCE(ncells=c(A=400, B=300, C=200), ngenes=300, dbl.rate=0.0001)
sce <- sce[, sce$type == "singlet"]
x <- counts(sce); cl <- droplevels(sce$cluster)
cm <- sapply(levels(cl), function(k) rowMeans(x[, cl == k]))
combos <- list("A+B"=cm[,"A"]+cm[,"B"], "A+C"=cm[,"A"]+cm[,"C"], "B+C"=cm[,"B"]+cm[,"C"])
mislabelled <- function(ad){
  w <- grepl("^dbl\\.", colnames(ad$counts))             # the cross-cluster doublets
  best <- apply(as.matrix(ad$counts[, w]), 2, function(v)
    names(combos)[which.max(sapply(combos, function(m) cor(log1p(v), log1p(m))))])
  mean(best != as.character(ad$origins)[w])
}
set.seed(2); mislabelled(getArtificialDoublets(x, n=600, clusters=cl))                 # 0.476
set.seed(2); mislabelled(getArtificialDoublets(x, n=600, clusters=cl, adjustSize=0))   # 0
```

pairs <- cbind(1:4, 5:8)

**Session info**

Numbers above from scDblFinder 1.16.0 (Bioconductor 3.18, R 4.3.3, xgboost 3.2.1); the same mislabelling fraction on 1.8.0 and 1.12.0 built from their release commits, and 39 % on 1.4.0. `R/getArtificialDoublets.R` is unchanged on `devel` (2d0e5e4), so the current version behaves the same. [submitter: paste `sessionInfo()` of the environment the MRE was run in]

**Fix**

A PR follows: sum every pair in the input order and replace the adjusted ones in place (`x1[,wAd] <- x2`), count the halving over all pairs, and scale with `Matrix::Diagonal` so that one adjusted pair works. With it, 0 of 650 cross-cluster doublets are mislabelled, `mostLikelyOrigin` is right for 100 % of the simulated heterotypic doublets, and the package's tests pass.
