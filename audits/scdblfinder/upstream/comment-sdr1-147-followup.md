Thanks for picking this up so quickly! I tried the four lines from e7a0406 on their own, and two things
seem to keep it from working yet:

1. `NA_character` isn't defined in base R (the constant is `NA_character_`), so with e7a0406
   `d$cluster <- NA_character` stops with `object 'NA_character' not found` whenever `clusters` is given,
   including `clusters=TRUE`. Runs with the default `clusters=NULL` are unaffected.

2. Even with `NA_character_`, the factor re-assignment brings the codes back. `d` is a base `data.frame`
   at that point (from `.evaluateKNN`), and assigning a factor into its character column stores the integer
   codes as strings:

   ```r
   d <- data.frame(row.names=paste0("c",1:4), type=rep("real",4), cluster=rep(NA,4))
   clusters <- factor(c("T","B","T","NK"), levels=c("B","NK","T"))
   d$cluster <- NA_character_
   d[row.names(d),"cluster"] <- as.character(clusters)
   d[row.names(d),"cluster"] <- factor(d[row.names(d),"cluster"], levels(clusters))
   d$cluster
   #> [1] "3" "1" "3" "2"
   ```

   Without the `if(is.factor(clusters))` block, the column holds `"T" "B" "T" "NK"`.

So the smallest change that works is probably `NA_character_` plus dropping the re-assignment.
If you'd like the level order kept, setting the whole column at once does it:
`d$cluster <- factor(NA, levels(clusters)); d[colnames(sce),"cluster"] <- as.character(clusters)`.
Both give `"T" "B" "T" "NK"` on the same data.frame, though I haven't run them inside a full scDblFinder call. Happy to open a small PR for either if that helps.
