Title: `doubletThresholding(method="dbr")` returns `NaN` on a table with only a `score` column

**Describe the bug**

The documentation says `d` is "minimally containing a `score` column" and that method `"dbr"` is "strictly based on the expected doublet rate". `doubletThresholding` first corrects `dbr` for homotypic doublets with `.estimateHeterotypicDbRate`, which, without a `cluster` column, estimates the unrecognisable proportion from the artificial doublets' scores; with no artificial rows that proportion is 0/0, the corrected rate is `NaN`, and so are the threshold and every call.

**MRE -- Minimal example to reproduce the bug**

```r
library(scDblFinder)
d <- data.frame(score=runif(1000))
doubletThresholding(d, dbr=0.05, method="dbr", returnType="threshold")   # NaN
table(doubletThresholding(d, dbr=0.05, method="dbr"), useNA="ifany")     # 1000 NA
```

With a `cluster` column the threshold is the 1 − dbr·(1 − Σpᵢ²) quantile, as intended.

**Traceback**

Not an R error.

**Session info**

scDblFinder 1.16.0 (Bioconductor 3.18, R 4.3.3), also 1.8.0 and 1.12.0; `R/doubletThresholding.R` is the same on `devel` (2d0e5e4). [submitter: paste `sessionInfo()`]

**Fix**

A PR follows: return the given rate from `.estimateHeterotypicDbRate` when there are no artificial doublets, so the threshold is the 1 − dbr quantile of the scores.
