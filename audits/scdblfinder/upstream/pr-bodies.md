### PR 1 — `fix/artificial-doublet-order` — "createDoublets: keep the input pair order when adjusting library sizes"

Fixes #NNN.

With `adjustSize > 0` (the `getArtificialDoublets` default is 0.25), `createDoublets` built the
non-adjusted doublets first and appended the size-adjusted ones, so the returned columns were no
longer in the order of the input pairs. `getArtificialDoublets` assigns the origins by position, so
about half of the cross-cluster artificial doublets carried another pair's origin label, and
`scDblFinder.mostLikelyOrigin` was right for 24 % of the heterotypic doublets on simulated data (100 %
with the order kept). The doublet calls do not depend on the origins and are unchanged.

The same block reassigned `dbl.idx` to the adjusted subset, so the halving that follows was applied
to `ceiling(halfSize × number of adjusted pairs)` doublets instead of `ceiling(halfSize × pairs)`, and
when exactly one pair was selected for adjustment (`length(wAd) > 1` guard) that pair was dropped and
the halving step failed with a subscript error.

This sums every pair in the input order and replaces the adjusted ones in place, counts the halving
over all pairs, and scales with `Matrix::Diagonal` so a single adjusted pair works. On 1.16.0 with
the change: 0 of 650 cross-cluster artificial doublets mislabelled (48.8 % before), `mostLikelyOrigin`
100 % on the simulation, 20 of 40 pairs halved at `halfSize=0.5`, 4 pairs → 4 doublets; the 17
testthat tests pass.

### PR 2 — `fix/factor-cluster-labels` — "scDblFinder: keep factor cluster labels as labels in the results table"

Fixes #NNN.

`d$cluster` is initialised to `NA` and then filled by position; a factor assigned that way is stored as
its integer codes, while the artificial doublets' origins are built from the level names. With
`clusters` given as a factor (a colData column, or `mockDoubletSCE()$cluster`)
`metadata(sce)$scDblFinder.stats` reports `observed = 0` for every combination with `NA` FNR and
difficulty, `plotDoubletMap` has nothing to show, and `scDblFinder.cluster` in the output holds the
codes instead of the labels. Character and integer labels are unaffected.

This converts a factor to character before the assignment. On 1.16.0 with the change, a factor gives
`sum(observed)` = 80 = the number of called doublets (0 before) and the label column; the 17 testthat
tests pass.

### PR 3 — `fix/dbr-threshold-without-artificial` — "doubletThresholding: do not correct dbr for homotypic doublets when there are no artificial doublets"

Fixes #NNN.

`doubletThresholding(d, dbr=x, method="dbr")` on a table that has only a `score` column (the
documented minimal input) returned `NaN`: the homotypic correction estimates the unrecognisable
proportion from the artificial doublets' scores, and with none of them the proportion is 0/0. This
returns the given rate in that case; the threshold is then the 1 − dbr quantile of the scores as
documented. With a `cluster` column nothing changes.
