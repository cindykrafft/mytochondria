Title: Gene set size filter is skipped entirely when -set_min equals -set_max (all sizes analysed; a set with an id absent from the data then fails the run)

<!-- GSEA-MSigDB/gsea-desktop has no issue template; CONTRIBUTING.md asks for a title, a clear description and a code sample / executable test case. -->

**Summary**

`GeneSetCohort.Generator.filterGeneSetsByMembersAndSize` (`GeneSetCohort.java:188-197`) applies the min/max size filters only `if (geneSetMinSize != geneSetMaxSize)`; the `else` branch (`// @note hack`) logs "Skipped gene set size filtering: max and min thresholds are equal" and keeps every set. The two parameters are documented as "Gene sets smaller/larger than this number are EXCLUDED from the analysis", so `-set_min 20 -set_max 20` (which a user reading the documentation takes as "exactly 20 genes") analyses sets of any size, and the reported FDRs are computed over that larger collection. The skipped branch is also the only place where each set is restricted to the identifiers present in the ranked list (`cloneDeep(rl)`), so with equal thresholds any set containing an identifier that is not in the data — the normal case with an MSigDB collection — aborts the run with `IllegalArgumentException: No such name: ...` from `Weighted.<init>`.

Same behaviour on `master` (`dc35c76`) and on the 4.4.0, 4.3.2, 4.1.0 and 4.0.3 tags.

**Executable test case** (`mcve_gs2_set_min_equals_max.sh`; a 30-gene list, sets of sizes 5, 10 and 20, and a second collection with one extra set carrying an identifier that is not in the list):

```sh
D=$(mktemp -d)
for i in $(seq 1 30); do printf 'g%d\t%d\n' $i $((31 - i)); done > $D/list.rnk
{ printf 'SIZE5\tna'; for i in $(seq 1 5); do printf '\tg%d' $i; done; printf '\n'
  printf 'SIZE10\tna'; for i in $(seq 1 10); do printf '\tg%d' $i; done; printf '\n'
  printf 'SIZE20\tna'; for i in $(seq 6 25); do printf '\tg%d' $i; done; printf '\n'; } > $D/sets.gmt
{ cat $D/sets.gmt; printf 'SIZE10_ABSENT\tna'; for i in $(seq 11 20); do printf '\tg%d' $i; done; printf '\tNOT_IN_LIST\n'; } > $D/sets_absent.gmt
run() { gsea-cli.sh GSEAPreranked -rnk $D/list.rnk -gmx $1 -collapse No_Collapse -set_min $2 -set_max $3 -nperm 10 \
        -rnd_seed 149 -plot_top_x 0 -make_sets false -zip_report false -gui false -out $D -rpt_label $4 > $D/$4.log 2>&1
        echo "$4: $(cut -f1 $D/$4.GseaPreranked.*/gsea_report_for_na_*_*.tsv 2>/dev/null | grep -v '^NAME' | sort | tr '\n' ' ')"; }
run $D/sets.gmt 10 11 control
run $D/sets.gmt 10 10 equal
run $D/sets_absent.gmt 10 10 equal_absent
```

Expected: `control` and `equal` both analyse `SIZE10` only; `equal_absent` analyses `SIZE10` and `SIZE10_ABSENT` (restricted to its 10 present genes).

Got on `master`:

```
control (-set_min 10 -set_max 11): analysed SIZE10 
equal (-set_min 10 -set_max 10): analysed SIZE10 SIZE20 SIZE5 
equal_absent (-set_min 10 -set_max 10): FAILED: Exception: No such name: NOT_IN_LIST
```

Shrinking the example showed nothing else is needed: any collection and any list reproduce it as soon as the two thresholds are equal, and the failure in the third run needs only one identifier absent from the list.

**Fix**

Run the two filters unconditionally (the `>= min` / `<= max` comparisons already handle `min == max`). A patch with that change and a unit test (`GeneSetCohortGeneratorTest`: inclusive range, restriction to the ranked list, and the equal-thresholds case; the last fails on `master`) is ready and can follow as a pull request. If the equal-thresholds branch was meant as a "no size filter" switch, the alternative is to keep it but still restrict the sets to the ranked list and say so in the parameter description.
