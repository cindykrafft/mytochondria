Title: weighted_p1.5 scoring scheme: hit weights of gene-set members with a negative ranking score are 1e-6 instead of |score|^1.5 / N_R

<!-- GSEA-MSigDB/gsea-desktop has no issue template; CONTRIBUTING.md asks for a title, a clear description and a code sample / executable test case. -->

**Summary**

With `-scoring_scheme weighted_p1.5`, `GeneSetScoringTables.WeightedOnePointFive.getHitScore` computes `Math.pow(score, 1.5)` on the *signed* score (`GeneSetScoringTables.java:228`). For a negative score that is `NaN`, and line 230 then substitutes `0.000001f`. The normaliser built in the constructor (line 210) uses `Math.pow(Math.abs(score), 1.5)`, so the hit weights of a set no longer sum to one: every member on the negative side of the ranked list adds 1e-6 to the running sum instead of |score|^1.5 / N_R. A set enriched at the bottom of the list, or with members on both sides, gets a wrong enrichment score; the NES, p-value and FDR built on it are wrong too. `weighted` (|score|) and `weighted_p2` (score * score) are not affected.

Reproduced on `master` (`dc35c76`) and on the 4.4.0, 4.3.2 tags; 4.1.0 and 4.0.3 carry the earlier form of the same code (`Math.pow(score, 0.5)` for the hit, |score|^1.5 for the normaliser, no absolute value), which is wrong for every set.

**Executable test case** (`mcve_gs1_weighted_p15.sh`; twelve genes scored 6..1, −1..−6, one set {g, i, k} with scores −1, −3, −5):

```sh
D=$(mktemp -d)
printf 'a\t6\nb\t5\nc\t4\nd\t3\ne\t2\nf\t1\ng\t-1\nh\t-2\ni\t-3\nj\t-4\nk\t-5\nl\t-6\n' > $D/list.rnk
printf 'NEG_SPREAD\tna\tg\ti\tk\n' > $D/set.gmt
for scheme in weighted_p1.5 weighted_p2; do
  gsea-cli.sh GSEAPreranked -rnk $D/list.rnk -gmx $D/set.gmt -collapse No_Collapse -scoring_scheme $scheme \
      -set_min 3 -set_max 12 -nperm 10 -rnd_seed 149 -plot_top_x 0 -make_sets false -zip_report false -gui false \
      -out $D -rpt_label $scheme > /dev/null 2>&1
  echo "$scheme: $(cut -f1,4,5 $D/$scheme.GseaPreranked.*/gsea_report_for_na_neg_*.tsv | sed -n 2p)"
done
```

Expected, from the definition of P_hit with |r_j|^p weights (N_R = 1 + 3^1.5 + 5^1.5 = 17.38; the running sum is −0.667 after the six positive misses, −0.609 after g, −0.720 after the miss h, −0.421 after i, −0.532 after j, +0.111 after k, 0 at the end):

```
weighted_p1.5: NEG_SPREAD 3 -0.7202
weighted_p2:   NEG_SPREAD 3 -0.7492
```

Got on `master`:

```
weighted_p1.5: NEG_SPREAD 3 -0.999997   (NAME SIZE ES)
weighted_p2: NEG_SPREAD 3 -0.74920636   (NAME SIZE ES)
```

With the hits worth 1e-6 the running sum only falls: −0.667, −0.778, −0.889, −1.0, so the reported ES is −1.0 for *any* set whose members are all on the negative side, and the same happens to the members on the negative side of a mixed set. Shrinking the example showed the condition is exactly "a member with score < 0": a set of positive-scored genes is scored correctly under `weighted_p1.5`.

On a synthetic 3,000-gene list (1,576 negative scores) with 1,000 gene-set permutations, comparing the report's ES against the |r|^1.5 definition: a 100-gene set spread over the bottom fifth of the list is reported as ES −0.9999 instead of −0.8276; an 80-gene set drawn from the negative half as −0.9999 instead of −0.6087; a 100-gene random set as −0.4544 instead of +0.2699 (NES −0.87 instead of a positive NES); sets on the positive side match to 1e-7. Under `weighted_p2` and `weighted` the same sets match the definition to 2e-7.

**Fix**

`Math.pow(Math.abs(score), 1.5)` in `getHitScore`, as in the constructor. A patch with that one-line change and a unit test class for the three weighted scoring tables (`GeneSetScoringTablesTest`, fails on `master`, passes with the change; the existing `XMathTest` and `VectorTest` unchanged) is ready and can follow as a pull request.
