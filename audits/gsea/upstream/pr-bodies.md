### PR 1 — `fix/weighted-p1.5-negative-scores` — "Fix weighted_p1.5 hit weights for negatively scored genes"

Fixes #NNN.

**Problem.** `GeneSetScoringTables.WeightedOnePointFive.getHitScore`
(`GeneSetScoringTables.java:226-231`) raises the signed rank metric to the power 1.5.
`Math.pow` of a negative base and a non-integral exponent is `NaN`, so `hitScore` is `NaN`
for every gene with a negative rank metric and the method falls back to `0.000001f`. The
constructor already normalises with `Math.abs` (line 210), so the numerator and the
denominator of P_hit disagree and the running enrichment score never rises inside a gene
set that lies on the negative side of the ranked list. Subramanian et al. 2005 weights a
hit by `|r_j|^p`; `weighted` and `weighted_p2` already do.

**Solution.** One line: use `Math.abs(score)` in `getHitScore`, with a comment saying why.

**Effect on results.** On a 20-gene ranked list whose answer can be worked out by hand
(−12/17 = −0.7058824), `weighted_p1.5` returned −0.999997 before and −0.7058824 after;
`weighted` and `weighted_p2` are unchanged. On an 8,000-gene list with 1,000 permutations,
four gene sets that disagreed with an independent implementation of the paper's algorithm
(one of them by a sign change, +0.3430 vs −0.3630) now agree exactly. Runs that use
`weighted`, `classic` or `weighted_p2` — including every default run — produce
byte-identical output.

**Tests.** Adds `src/test/java/edu/mit/broad/genome/alg/gsea/GeneSetScoringTablesTest.java`
(4 tests): the hit and miss weights of `weighted`, `weighted_p2` and `weighted_p1.5` on a
six-gene ranked list with positive and negative scores, and the `|score|^1.5` weights on a
set with two different magnitudes. Two of the four fail on unmodified master
(`negative-score hit (p=1.5) ==> expected: <0.5> but was: <1.0E-6>`) and all four pass with
this change. The repository's existing `XMathTest` and `VectorTest` (54 tests) pass before
and after; there is no `test` task in `build.gradle`, so they were compiled against
`build/libs/gsea-minimal-user.jar` plus `lib_test/` and invoked directly — happy to wire a
JUnit task into the build in a separate PR if that would be useful.

### PR 2 — `fix/set-size-filter-min-equals-max` — "Apply the gene set size filter when set_min equals set_max"

Fixes #NNN.

**Problem.** `GeneSetCohort.Generator.filterGeneSetsByMembersAndSize`
(`GeneSetCohort.java:188-197`) runs the size filter only when `geneSetMinSize !=
geneSetMaxSize`; the equal case falls into an `else { // @note hack }` branch that does
nothing. `-set_min 20 -set_max 20` therefore does not select the size-20 sets, it turns the
filter off, and every set in the GMT is scored and reported — with an FDR q and an FWER p
computed over that larger family. The same branch is where each set is restricted to the
genes present in the ranked list (`removeGeneSetsSmallerThan(gsets, min, rl)` →
`GeneSet.cloneDeep(rl)`), so with equal bounds a set holding a gene absent from the ranked
list aborts the run with `java.lang.IllegalArgumentException: No such name: <gene>`.

**Solution.** Run the two filters unconditionally. With equal bounds they keep exactly the
sets whose in-list size equals that value, which is what the parameter help describes, and
the intersection with the ranked list happens in every case.

**Effect on results.** Runs where `set_min` differs from `set_max` — the defaults are 15
and 500 — are unaffected: the same code runs in the same order. Runs with equal bounds now
report the sets of that size instead of all of them, and no longer abort on a set with a
member missing from the ranked list. Verified on a 4,000-gene list with sets of sizes 5,
15, 20, 100 and 600 across five bound pairs.

**Tests.** Adds
`src/test/java/edu/mit/broad/genome/alg/gsea/GeneSetCohortSizeFilterTest.java` (3 tests):
unequal bounds, equal bounds, and a set whose size must be counted after intersecting with
the ranked list. Two of the three fail on unmodified master (`array lengths differ,
expected: <1> but was: <4>`; `expected: <4> but was: <5>`) and all three pass with this
change. `XMathTest` and `VectorTest` (54 tests) pass before and after; see the note in PR 1
about how they are run.
