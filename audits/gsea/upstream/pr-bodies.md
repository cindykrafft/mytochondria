### PR 1 — `fix/weighted-p1.5-abs-score` — "Fixed the weighted_p1.5 hit weight for negative ranking scores"

Fixes #NNN.

`WeightedOnePointFive.getHitScore` computed `Math.pow(score, 1.5)` on the signed score,
which is NaN for a negative score and was then replaced by `0.000001f`. The normaliser in
the constructor already uses |score|^1.5, so every gene-set member on the negative side of
the ranked list contributed a hit weight of 1e-6 instead of |score|^1.5 / N_R, and sets
enriched at the bottom of the list (or with members on both sides) got a wrong enrichment
score under the `weighted_p1.5` scoring scheme (ES −1.0 for any set whose members are all
negative; on a synthetic list a random 100-gene set came out at ES −0.454 instead of
+0.270). This uses the absolute value, as the `weighted` and `weighted_p2` schemes
effectively do, so the hit weights of a set sum to one again.

Tests: new `GeneSetScoringTablesTest` (three tests on the weighted, weighted_p2 and
weighted_p1.5 tables; the two `weighted_p1.5` assertions fail on `master` and pass with
this change). `XMathTest` and `VectorTest` unchanged (55 tests pass before and after).

Behaviour change: only `-scoring_scheme weighted_p1.5` results change, and only for gene
sets with at least one member with a negative ranking metric. Results of the default
`weighted` scheme, `classic` and `weighted_p2` are unchanged.

### PR 2 — `fix/set-size-filter-min-equals-max` — "Apply the gene set size filter also when set_min equals set_max"

Fixes #NNN.

`GeneSetCohort.Generator.filterGeneSetsByMembersAndSize` skipped the min/max size filter
entirely when the two thresholds were equal (the branch was marked `// @note hack`), so
e.g. `-set_min 20 -set_max 20` analysed every gene set of every size although the
parameters are documented as excluding sets outside the range, and — because the skipped
branch is also where sets are restricted to the identifiers present in the ranked list —
a set with an identifier absent from the data then failed the run with "No such name".
This runs the two filters unconditionally; `removeGeneSetsSmallerThan` / `LargerThan`
use `>=` / `<=`, so equal thresholds keep exactly the sets of that size, restricted to
the data.

Tests: new `GeneSetCohortGeneratorTest` (inclusive range and restriction to the ranked
list; equal thresholds keep only the sets of that size — the second fails on `master`).
`XMathTest` and `VectorTest` unchanged.

Behaviour change: runs with `set_min == set_max` now analyse only the sets of that size
(previously all sets, or a failure). If the equal-thresholds branch was intended as a
"no size filter" switch, say so and I will instead keep it, add the restriction to the
ranked list, and document it in the parameter description.

### PR 3 — `fix/zero-weight-gene-set` — "Give equal hit weights to a gene set whose members all have a ranking score of 0"

Fixes #NNN.

Under the weighted schemes the hit weight is |score|^p / N_R with N_R summed over the set's
members present in the ranked list. When every present member has score 0 (a preranked
list that gives untested genes a statistic of 0, and a set of genes that are all
unexpressed), N_R is 0, the hit weight is 0/0 = NaN, and in `KSCore` the running sum turns
NaN at the first hit; every later comparison against the NaN is false, so the ES that
survives is the running sum just before the first hit, −(rank of first member)/(N − N_H),
and it is reported with an NES, p-value and FDR (p = 0 when the block of zeros sits low
in the list). Equal scores mean equal weights, so this returns 1/N_H from `getHitScore`
of the three weighted tables when the total weight is 0 — the ES then equals the classic
ES, which is finite — and logs a warning naming the set, since its score then depends only
on where its tied genes sit in the list. Excluding such sets from the run with the same
warning would be the alternative; happy to switch if you prefer that.

Tests: new `ZeroWeightGeneSetTest` (equal hit weights for the three schemes; the weighted
ES of an all-zero set is finite and equals the classic ES — both fail on `master`).
`XMathTest` and `VectorTest` unchanged.

Behaviour change: only gene sets whose present members all have score 0 are affected;
every other set's hit weights are unchanged.
