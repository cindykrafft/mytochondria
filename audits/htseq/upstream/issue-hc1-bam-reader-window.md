Title: [BUG] `BAM_Reader[iv]` misses alignments whose last base is `iv.start` (fetch called with `iv.start + 1`)

<!-- htseq/htseq .github/ISSUE_TEMPLATE/bug_report.md fields -->

**Software versions**
- `HTSeq` 2.1.2 (PyPI wheel) and `main` @ `7672321` (editable install); the same line is in 0.9.1, 0.11.2, 0.12.4 and 0.13.5 (reproduced by execution on 0.11.2, 0.12.4 and 0.13.5 built from the sdists)
- `Python` 3.12.3, pysam 0.24.0
- Linux (x86_64)
- aligner: not relevant (the example writes the BAM with pysam)

**Describe the bug**

`BAM_Reader.__getitem__` (`HTSeq/__init__.py`) does

```python
        for pa in self.sf.fetch(iv.chrom, iv.start + 1, iv.end):
```

`pysam.AlignmentFile.fetch` takes 0-based, half-open `start`/`stop`, the same convention as `GenomicInterval`, so the query window is shifted right by one base: an alignment whose last aligned base is `iv.start` overlaps `iv` (its `GenomicInterval.overlaps(iv)` is `True`, and `fetch(iv.chrom, iv.start, iv.end)` returns it) but `reader[iv]` does not return it. This is the interface the `doc/tutorials/tss.rst` tutorial uses (`sortedbamfile[window]`); any per-window count or coverage profile built with it is short by the reads that end exactly at the window's first base.

**Expected:** `reader[iv]` returns every alignment overlapping `[iv.start, iv.end)`, i.e. the two reads below.
**Got** (2.1.2 and `main`): only `inside`; `covers_base_100` (aligned to `[91, 101)`) is missing.

On 300 random windows over 2,000 random reads, 7 windows lose one overlapping read each, and every missed read ends exactly at `iv.start + 1`; no non-overlapping read is ever returned. Shrinking showed the shift is independent of strand, read length and window length.

**Minimal example showing the bug**

The script writes the 2-read BAM itself; nothing needs to be attached.

```python
# mcve_hc1_bam_reader_window.py
import pysam
import HTSeq

fn = "two_reads.bam"
with pysam.AlignmentFile(fn, "wb", header={"HD": {"VN": "1.6", "SO": "coordinate"},
                                           "SQ": [{"SN": "chr1", "LN": 1000}]}) as f:
    for name, start in (("covers_base_100", 91), ("inside", 95)):  # 10-nt reads: [91,101) and [95,105)
        a = pysam.AlignedSegment()
        a.query_name, a.query_sequence, a.flag = name, "A" * 10, 0
        a.reference_id, a.reference_start, a.mapping_quality, a.cigartuples = 0, start, 60, [(0, 10)]
        a.query_qualities = pysam.qualitystring_to_array("I" * 10)
        f.write(a)
pysam.index(fn)

iv = HTSeq.GenomicInterval("chr1", 100, 200, ".")
got = [a.read.name for a in HTSeq.BAM_Reader(fn)[iv]]
expected = [a.read.name for a in HTSeq.BAM_Reader(fn) if a.iv.overlaps(iv)]
print("HTSeq", HTSeq.__version__, "| reader[iv]:", got, "| records with iv.overlaps:", expected)
assert got == expected, "reader[iv] should return every alignment overlapping iv"
```

**Proposed fix:** `self.sf.fetch(iv.chrom, iv.start, iv.end)`. A branch with that one-line change, a regression test (`test/test_parsers.py::test_bam_reader_getitem_window`, which fails on `main` and passes with the fix) and a `doc/history.rst` entry is ready; PR follows. `htseq-count` is not affected (it iterates the file rather than indexing it).
