### PR 1 — `fix/palindrome-mismatch-penalty` — "Fix: charge Q/10 per mismatch in ILLUMINACLIP palindrome mode"

Fixes #NNN.

`IlluminaPrefixPair.calculatePalindromeDifferenceQuality` computed the
per-mismatch penalty as `-qual1 / 10` on `int` operands, so the result was
truncated toward zero before being widened into the `float likelihood[]` array.
A mismatch at Q0–Q9 cost 0.0 instead of 0.0–0.9, one at Q10–Q19 cost 1.0 instead
of 1.0–1.9, and so on.

`README.md` documents one rule for both modes — "each matching base adds just
over 0.6, while each mismatch reduces the alignment score by Q/10" — and simple
mode already implements it as `-quals[recPos] / 10.0f` in
`IlluminaClippingSeq.calculateDifferenceQuality`. Palindrome mode was the only
place in the file where the division was integer.

The error is one-sided: the penalty is always too small, so the palindrome score
is always too high, so pairs whose read-through alignment scores *below*
`palindromeClipThreshold` are clipped — and with the default
`keepBothReads=false` the reverse read is dropped.

**The change.** Two characters: `10` → `10.0f` on the two branches of the
mismatch case.

**The test.** `IlluminaPalindromeMismatchPenaltyTest` follows the existing
`IlluminaPalindrome*Test` classes (`addPrefixPair` on a trimmer built with
`new IlluminaClippingTrimmer(mock(Logger.class), 2, 30, 10, 8, false)`, then
`processRecords` on a constructed pair). Geometry: a 40 nt insert read through
into the stock TruSeq3 `PrefixPE` adapters, 50 nt reads, 60 aligned bases, six
mismatches in read 2 placed outside both 16-mer seeds.

| test | score by the README | on unmodified `main` |
|---|---|---|
| perfect read-through (positive control) | 36.12 | passes |
| six mismatches at Q2 | 31.31, above 30 → clip | passes |
| six mismatches at Q19 | 21.11, below 30 → leave | passes |
| six mismatches at Q9 | 27.11, below 30 → leave | **fails**: read 2 is dropped |

Only the last one fails without the fix, so the class is a regression test and
not a restatement of the patch.

**Numbers.** `mvn test` on unmodified `main` @ `ef98d62`: 259 tests, 0 failures.
The new class alone on unmodified `main`: 4 tests, 1 failure. With this branch:
263 tests, 0 failures. (This environment has javac 21, so every run added
`-Dmaven.compiler.release=21`; the sources compile unchanged under 21 and the

**Effect on real output.** On 4,000 synthetic 100 nt pairs with read-through
planted in 3,041 and quality-correlated errors, changing only the penalty
changes the outcome of 49 pairs (1.2 %). On a NovaSeq-like binned quality
profile and on uniformly Q30–41 data, 0 of 4,000 change — the fix is invisible
on clean data and only matters where mismatches inside the overlap fall on bases
below Q10.
