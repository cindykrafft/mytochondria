Title: ILLUMINACLIP palindrome mode charges int(Q/10) per mismatch instead of Q/10 (integer division), unlike simple mode and the README

<!-- usadellab/Trimmomatic has no issue template; sections follow the README's own order: what was run, what happened, what was expected. -->

**Version:** `main` @ ef98d62 (0.41), and every release run: 0.41, 0.40, 0.39 (release jars), 0.38, 0.36, 0.33, 0.32 (built from the tags). Java 25.0.4, Ubuntu 24.04.

**What happened**

The README ("The Adapter Fasta") says that in the alignment score "each matching base adds just over 0.6, while each mismatch reduces the alignment score by Q/10". Simple mode does that (`IlluminaClippingTrimmer.java:556`, `-quals[recPos] / 10.0f`). Palindrome mode divides two `int`s (`IlluminaClippingTrimmer.java:494` and `:496`, `likelihood[i] = -qual1 / 10;`), so the penalty is truncated to a whole number: a mismatch at Q2–Q9 costs nothing, at Q19 it costs 1 instead of 1.9, at Q39 it costs 3 instead of 3.9. The score of every palindrome alignment with mismatches at qualities that are not multiples of 10 is therefore too high, and pairs whose true score is just below `palindromeClipThreshold` are clipped anyway (forward read cut to the insert, reverse read dropped unless `keepBothReads`).

**Minimal example** (`mcve_tm1_palindrome_penalty.py <trimmomatic.jar> <adapters/TruSeq3-PE.fa>`): one 2x50 pair with a 42-base insert that reads through into the TruSeq3 adapters, with two sequencing errors in read 1 at Q19. The palindrome alignment covers 58 bases with 56 matches:

```
documented: 56 * 0.60206 - 2 * 1.9 = 29.9  (< 30: leave the pair alone)
shipped:    56 * 0.60206 - 2 * 1   = 31.7  (>= 30: clip read 1 to 42 bases, drop read 2)
```

```python
#!/usr/bin/env python3
import os, subprocess, sys, tempfile
jar, fa = sys.argv[1], sys.argv[2]
r1 = "CAGCTTTTTATATTATGCAGAAAATCTACTTCGCCTGATACGAGATCGGA"; q1 = "III4IIII4IIIIIIIIIIIIIIIIIIIIIIIIIIIIIIIIIIIIIIIII"
r2 = "CGTATCAGGCGAAGTAGATTTTCTGCATAATATGAAAATCTGAGATCGGA"; q2 = "I" * 50
d = tempfile.mkdtemp()
open(os.path.join(d, "r1.fq"), "w").write("@p\n%s\n+\n%s\n" % (r1, q1))
open(os.path.join(d, "r2.fq"), "w").write("@p\n%s\n+\n%s\n" % (r2, q2))
outs = [os.path.join(d, x) for x in ("1P.fq", "1U.fq", "2P.fq", "2U.fq")]
cmd = ["java", "-jar", jar, "PE", "-threads", "1", "-phred33", os.path.join(d, "r1.fq"), os.path.join(d, "r2.fq")] + outs + ["ILLUMINACLIP:%s:2:30:10" % fa]
p = subprocess.run(cmd, capture_output=True, text=True)
print([l for l in (p.stdout + p.stderr).splitlines() if l.startswith("Input Read Pairs")][0])
print("expected: Both Surviving: 1 (58 aligned bases, 56 matches: 56*0.60206 - 2*1.9 = 29.9 < 30)")
print("got     : forward-only survivor of length %d" % len(open(outs[1]).read().split("\n")[1]) if os.path.getsize(outs[1]) else "got     : both reads kept")
```

Output on `main` (ef98d62), 0.41 and 0.39:

```
Input Read Pairs: 1 Both Surviving: 0 (0.00%) Forward Only Surviving: 1 (100.00%) Reverse Only Surviving: 0 (0.00%) Dropped: 0 (0.00%)
expected: Both Surviving: 1 (58 aligned bases, 56 matches: 56*0.60206 - 2*1.9 = 29.9 < 30)
got     : forward-only survivor of length 42
```

Moving the same two errors to Q20 (penalty 2 under both rules, score 29.7) leaves the pair untouched, and a single Q19 error (32.4) clips it under both rules, so the difference is exactly the truncated penalty. Shrinking showed that the read pair, adapters and insert do not matter: any palindrome alignment whose documented score sits in [threshold − Σ frac(Q/10), threshold) is affected.

**How often**: on a grid of 7,200 synthetic 2x50 pairs (insert 42, 1–3 read-1 errors at Q2–Q40) the shipped decision differs from the documented one for 600 pairs (all with Q15/Q19 errors); a port of the integer rule reproduces the shipped decisions 7,200/7,200. In a simulated 2x50 library with an Illumina-like quality profile 23 of 4,000 pairs flip (both rules clip the same 1,745 pairs otherwise); for 2x75, 2x100 and 2x150 libraries the palindrome alignments are long enough that no pair flips at threshold 30. So this matters for short reads or short overlaps, where a couple of mismatches decide, and it silently makes palindrome clipping more permissive than documented and than simple mode.

**Fix**: divide by `10.0f` at `IlluminaClippingTrimmer.java:494` and `:496`, as simple mode already does. A branch with the two-character fix and a regression test (`IlluminaPalindromeMismatchPenaltyTest`, fails on unmodified `main`, passes with the fix; full suite 259 → 261 tests passing) is ready; PR follows.
