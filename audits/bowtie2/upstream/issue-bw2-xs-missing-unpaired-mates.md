Title: XS:i is never printed for a mate reported as an unpaired alignment (YT:Z:UP), even when it has a second-best alignment and MAPQ 0/1

<!-- BenLangmead/bowtie2 has no issue template. Second filing (with PR). Every version. -->

**Versions:** 2.3.5.1, 2.4.2, 2.4.5, 2.5.1, 2.5.4 and `master` @ 58e34bf, same behaviour.

`SamConfig::printAlignedOptFlags` (`sam.cpp`) chooses the source of `XS:i` by whether the read is part of a pair:

```cpp
if(flags.partOfPair()) {
    sco = summ.bestUnchosenPScore(rd.mate < 2);
} else {
    sco = summ.bestUnchosenUScore();
}
```

For a mate that is reported as an unpaired alignment because the pair aligned neither concordantly nor discordantly (`YT:Z:UP`), `AlnSinkWrap::finishRead` builds the `AlnSetSumm` from that mate's unpaired alignments only (`summ1.init(rd1_, NULL, NULL, NULL, &rs1u_, NULL, ...)`), and `selectByScore` with `rs2 == NULL` fills `bestUnchosenUScore` but leaves `bestUnchosenP1Score`/`P2Score` invalid. `flags.partOfPair()` is still true for such a mate, so `XS:i` is omitted. The MAPQ for the same record is computed through `AlnSetSumm::bestUnchosenScore(mate1)`, which returns the unpaired second-best when the summary is not paired, so the record does get MAPQ 0 or 1, and the alignment summary counts it under "aligned >1 times" — but the tag is missing.

**Reproduction:** a 120-kb random reference in which a 2-kb segment is duplicated exactly; 30 pairs whose mate 1 comes from the duplicated segment and whose mate 2 is random sequence (unalignable); default options.

```
mate 1 records:  FLAG 73/89, YT:Z:UP, MAPQ 1 (30 of 30), XS:i present on 0 of 30
summary:         30 pairs aligned 0 times concordantly or discordantly; of these:
                   60 mates make up the pairs; of these:
                     30 (50.00%) aligned 0 times
                     0 (0.00%) aligned exactly 1 time
                     30 (50.00%) aligned >1 times
```

The same 30 reads given as unpaired input (`-U`) get `XS:i:0`; and concordant pairs from the duplicated segment get `XS:i` on both mates. Script: `a1_summary_arithmetic.py` in the repository linked below (the "one_mate_dup" class).

Many pipelines treat the absence of `XS:i` as "uniquely mapped" (it is the usual recipe for Bowtie 2 output), so a multi-mapping mate whose partner failed to align passes as unique.

**Fix:** use `summ.bestUnchosenScore(rd.mate < 2)`, which is what the MAPQ calculation already uses (paired second-best for concordant/discordant pairs, unpaired second-best otherwise). With it the 30 records above carry `XS:i:0`; concordant and discordant pairs and unpaired reads are unchanged. PR follows.
