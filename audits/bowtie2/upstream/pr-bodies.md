### PR 1 — `fix/mate2-mapq-opposite-length` — "Use the opposite mate's length when computing mate 2's MAPQ"

Fixes #NNN.

Since 41ee86b (`MQ:i` support) `AlnSinkSam::reportHits` computes mate 2's MAPQ with mate 2's own length passed in the opposite-mate slot, so `BowtieMapq2` sums the perfect and minimum scores of a concordant pair over mate 2 twice instead of mate 1 + mate 2. With mates of unequal length the two mates of the same pair get different MAPQs (40 and 23 for a 150/50-bp pair with 3 + 2 mismatches; 6 and 30 for a perfect 150/60-bp pair in a two-copy repeat). Releases up to 2.5.4 gave both mates the same value, as `appendMate` passed `rdo->length()`.

This passes `rd1`'s length. On the six pairs in the issue both mates now get the value a port of `BowtieMapq2` computes from the pair's scores and both read lengths, the same as 2.5.4; equal-length pairs and unpaired reads are unchanged. `scripts/test/simple_tests.pl` passes on the branch.

### PR 2 — `fix/xs-for-unpaired-mates` — "Report XS:i for mates aligned as unpaired alignments"

Fixes #NNN.

`printAlignedOptFlags` took `XS:i` from `bestUnchosenPScore()` for every read that is part of a pair. For a mate reported as an unpaired alignment (`YT:Z:UP`) the `AlnSetSumm` holds that mate's unpaired alignments only, so the paired second-best is never set and `XS:i` was omitted even when a second-best alignment exists — the record gets MAPQ 0 or 1 and the summary counts it under "aligned >1 times", but the tag is missing.

This uses `bestUnchosenScore()`, which the MAPQ calculation already uses: the paired second-best for concordant and discordant pairs, the unpaired second-best otherwise. On 30 pairs whose mate 1 lies in an exact duplication and whose mate 2 does not align, `XS:i:0` is now printed on all 30 mate-1 records (0 before); concordant pairs, discordant pairs and unpaired reads print the same tags as before. `scripts/test/simple_tests.pl` passes on the branch.
