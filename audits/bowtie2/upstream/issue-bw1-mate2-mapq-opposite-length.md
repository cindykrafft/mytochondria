Title: Since 41ee86b (MQ:i support) mate 2's MAPQ is computed with its own length in place of mate 1's, so mates of unequal length get different MAPQs for the same concordant pair

<!-- BenLangmead/bowtie2 has no issue template. First filing (with PR). Master-only regression, unreleased: file before 2.5.5 ships. -->

**Version:** `master` @ 58e34bf (VERSION 2.5.5); not in 2.5.4 or earlier releases (checked 2.3.5.1, 2.4.2, 2.4.5, 2.5.1, 2.5.4).

In `AlnSinkSam::reportHits` (`aln_sink.h`, added by 41ee86b "Add support for MQ:i SAM flag") the MAPQ of mate 2 is computed as

```cpp
itoa10<TMapq>(mapq.mapq(summ, *flags2, rd2->mate < 2,
                        rd2->length(),
                        rd2 == NULL ? 0 : rd2->length(),
                        mapqInps2), buf2);
```

The fifth argument is the opposite mate's length (`ordlen`); for mate 1 the call passes `rd2->length()`, for mate 2 it passes `rd2->length()` again instead of `rd1->length()`. Before 41ee86b `appendMate` passed `rdo == NULL ? 0 : rdo->length()`. `BowtieMapq2::mapq` sums `perfectScore` and `scoreMin` over `rdlen` and `ordlen` for a concordant pair, so mate 2's MAPQ is now computed as if the pair were two copies of mate 2. When the mates have the same length nothing changes; when they differ (as they do after adapter or quality trimming) the two mates of the same concordant pair get different MAPQs, in either direction.

**Reproduction** (100-bp and 50-bp mates from a random 60-kb reference, end-to-end mode, default options; the pairs are concordant and unique unless noted):

```
                                              mate 1 AS/MAPQ   mate 2 AS/MAPQ   2.5.4 (both mates)
150/50 bp, 3 + 2 mismatches, no second-best    -18 / 40         -12 / 23          40
150/75 bp, 4 + 1 mismatches, no second-best    -24 / 40          -6 / 24          40
150/50 bp in a 2-copy repeat, 1 + 1 mismatches  -6 / 17 (XS -24)  -6 / 16          17
150/60 bp in a 2-copy repeat, perfect             0 /  6 (XS -6)    0 / 30           6
--local, 150/50 bp in a repeat, 1 + 1 mm       292 / 14 (XS 268)  92 / 21          14
--local, 150/60 bp in a repeat, perfect        300 / 11 (XS 292) 120 / 14          11
```

A Python port of `BowtieMapq2` reproduces mate 1's value from the pair's AS/XS sums and both read lengths, and reproduces mate 2's value only when mate 2's length is used for both mates. Equal-length pairs (100/100) match the port on both mates.

Script: `m1_mapq.py` in the repository linked below builds the reference and pairs and prints the table for any `bowtie2-align-s`.

**Fix:** pass `rd1 == NULL ? 0 : rd1->length()` for mate 2 (PR follows). With that change every pair above gives both mates the same MAPQ as the port and as 2.5.4.
