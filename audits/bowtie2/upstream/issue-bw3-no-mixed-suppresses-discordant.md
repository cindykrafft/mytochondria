Title: --no-mixed also suppresses discordant alignments; the manual says only the per-mate fallback is disabled

<!-- BenLangmead/bowtie2 has no issue template. Third filing (report; code or manual, maintainers' choice). Every version. Send after BW1 or BW2 has a reply. -->

**Versions:** 2.3.5.1, 2.4.2, 2.4.5, 2.5.1, 2.5.4 and `master` @ 58e34bf.

The manual documents `--no-mixed` as: "By default, when bowtie2 cannot find a concordant or discordant alignment for a pair, it then tries to find alignments for the individual mates. This option disables that behavior." — with `--no-discordant` as the separate switch for discordant alignments, and the "Mixed mode" section saying `--no-mixed` "will only consider alignment status of pairs per se".

In the code a discordant pair is assembled from the two mates' unpaired alignments (`AlnSinkWrap::prepareDiscordants`: `rs1u_.size() == 1 && rs2u_.size() == 1`), and unpaired alignments are only stored while `ReportingState::doneUnpaired(mate)` is false; `ReportingState::nextRead` sets `doneUnpair1_ = doneUnpair2_ = !p_.mixed` for every pair. So with `--no-mixed` no unpaired alignment is ever kept, no discordant pair can be formed, and the discordant line of the summary is always 0.

**Reproduction:** 120-kb random reference; 80 pairs built to be discordant (50 with mates 5 kb apart in FR orientation, 30 with both mates forward 200 bp apart) among 320 other pairs; default options vs `--no-mixed` (no `--no-discordant`).

```
default:      80 pairs YT:Z:DP, FLAG 97/145 (161/81), TLEN set
              "80 (42.11%) aligned discordantly 1 time" ... "82.00% overall alignment rate"
--no-mixed:   0 pairs YT:Z:DP; the 80 pairs are reported unaligned (FLAG 77/141, YT:Z:UP)
              "0 (0.00%) aligned discordantly 1 time" ... "58.00% overall alignment rate"
```

Script: `a1_summary_arithmetic.py` in the repository linked below. Either the unpaired search should still run when discordant alignments are wanted (reporting only the discordant pair, not the single mates), or the manual entries for `--no-mixed`, `--no-discordant` and "Mixed mode" should say that `--no-mixed` implies no discordant alignments. Happy to send a PR for whichever you prefer.
