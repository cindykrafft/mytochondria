# Issue: Monte Carlo p-values exclude ties; p = 0 with cfg.numrandomization = 'all'

**Target:** `fieldtrip/fieldtrip` (issue first — this changes reported p-values, so maintainers should see the reasoning; the PR references it)

## Title

```
Permutation p-values use strict > and exclude ties: p = 0 with numrandomization='all', anti-conservative maxsize clusters
```

## Body

```markdown
**Description of the problem**

`private/clusterstat.m` and `ft_statistics_montecarlo.m` compare the observed statistic with the randomization distribution using strict inequalities, e.g.

    prob(j) = sum(posdistribution>stat(j))/Nrand;              % numrandomization = 'all'
    prob(j) = (sum(posdistribution>stat(j)) + 1)/(Nrand + 1);  % random subset
    prb_pos = prb_pos + (statobs<statrand);                    % uncorrected / max

The permutation p-value is the proportion of randomizations *at least as extreme* as the observed statistic (Maris & Oostenveld 2007; Phipson & Smyth 2010), i.e. `>=`. The strict form has two visible consequences:

1. **`cfg.numrandomization = 'all'`.** The enumerated set contains the identity permutation (resampledesign emits the all-zeros sign-flip pattern / `perms` contains the identity), which reproduces the observed statistic exactly. That tie is excluded, and on this path no `+1` is added, so every p-value is short by exactly `1/Nperm`, and the most extreme observed statistic is reported as **p = 0**. Reproduction (`ft_statfun_depsamplesT`, 10 paired subjects = 1024 sign flips, `correctm='no'`, `tail=1`):

        observed t = 6.294
        FieldTrip prob (numrandomization=all, tail=1) = 0.000000
        exact one-sided permutation p should be 1/1024 = 0.000977

        weaker effect: observed t = -0.762
        FieldTrip prob                       = 0.764648  (783/1024 = #{T >  tobs})
        standard exact p (#{T >= tobs}/1024) = 0.765625  (784/1024)

   This is the path `resampledesign` itself steers small paired designs onto ("better use cfg.numrandomization='all'").

2. **Integer-valued cluster statistics (`cfg.clusterstatistic='maxsize'`).** Ties between the observed cluster size and the largest randomization cluster are frequent and are all excluded, so cluster p-values are systematically too small. <!-- FT1B --> For the default `'maxsum'` on continuous t-values ties do not occur and nothing changes.

**Suggested fix**

Use `>=`/`<=` in all of these comparisons (clusterstat lines 414, 433, 435, 447, 449, 494, 513, 515, 527, 529; ft_statistics_montecarlo lines 378-379, 384-385). This is consistent with the existing `+1/(N+1)` convention for random subsets (which was added in 2012 for bug 783 but left the enumerated path and the tie handling as they were). PR to follow.

**Environment:** FieldTrip master @ 2e14f72; reproduced by running the shipped code under Octave 8.4. Standalone scripts: https://github.com/cindykrafft/research-software-audit/tree/main/audits/fieldtrip/verify
```
