## Comment for #2610

```markdown
Tests added and run.

**New test:** `test/test_pull2610.m` (`DATA no`) — compares `ft_connectivity_psi` against an independent implementation of the Nolte et al. (2008) definition at every frequency bin, including the bins whose window reaches the top of the range, and checks that the normalized variant is finite and matches its reference. Passes on this branch; fails on master (max abs diff 0.69 at the edge bins).

**Existing test:** `test_ft_connectivity_psi` initially failed on this branch, and the reason is instructive: its input has dimord `rpt_chan_chan`, i.e. no frequency axis, so the "slope across frequency" is computed over a single bin. On master the only nonzero output for that input was the raw imaginary coherency of the single bin — exactly the contamination this PR removes — so on this branch a one-bin PSI is 0 for any `nbin` and the assertion "different `nbin` give different results" cannot hold. I gave the test a 10-bin frequency axis (`rpt_chan_chan_freq`); the updated test passes on both master and this branch, and with a real frequency axis master and branch give identical results away from the edge bins (checked: max |PSI| 0.8652 on both).

`test_ft_connectivityanalysis` cannot run here on either master or the branch: `ft_specest_mtmfft` needs the two-output `dpss` from the MATLAB Signal Processing Toolbox, which neither Octave's signal package nor `external/signal/dpss_hack` provides. If someone with MATLAB can run it on the branch, that would be welcome; the only code changed is the `phaseslope` subfunction of `ft_connectivity_psi`.
```
