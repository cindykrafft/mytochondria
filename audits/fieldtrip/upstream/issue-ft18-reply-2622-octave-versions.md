FieldTrip's own `istable` is in `compat/matlablt2013b`, which is not added under Octave.

**Octave's history.** `startsWith` and `endsWith` are built in since Octave 7; they are in the list of new functions in Octave's NEWS for version 7. The built-in versions take a cell array of patterns: `startsWith({'abc','xbc','zz'}, {'x','ab'})` gives `[1 1 0]` on 8.4 and 10.3. `contains` and `istable` are still listed as unimplemented in Octave's `__unimplemented__.m`, in 8.4, 10.3 and the current development sources. The reason FieldTrip's shims were used on 8.4 is that `ft_defaults` adds `compat/octave` for every Octave version, and the shim's self-removal looks for the built-in with `which(mfilename, '-all')`, but Octave's `which` ignores `-all` ("not yet implemented - only the first result will be returned"). So the shim never finds the built-in and stays in front of it.

**A version-based approach would fit this.** Following your `matlablt` idea: move `startsWith.m` and `endsWith.m` into a folder that `ft_defaults` adds only for Octave versions before 7, the same way the `matlablt` folders are added, and keep `contains.m` in `compat/octave` with the cell-array fix, since no Octave version has `contains`. Octave 7 and later would then use the built-ins, and the remaining change stays inside `compat`, apart from the one `ft_defaults` line that adds the new folder.
