The cause is that `InfoFileWriter` slices `info.original_read` at the match coordinates, while the coordinates refer to the read after `--cut`/`--quality-cutoff`/`--nextseq-trim` have removed bases from its ends, so everything is shifted by the number of 5'-removed bases (and with `--revcomp`, by the number of 3'-removed bases). The fix records those counts in `ModificationInfo` and lets the writer add the removed bases back to the first record, so offsets and columns 5–7 refer to the original read as documented.
