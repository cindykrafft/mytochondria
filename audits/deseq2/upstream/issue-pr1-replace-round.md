TITLE: replaceOutliers: replacement counts are truncated, not rounded (systematic -0.5 bias)

**Summary.** In `replaceOutliers()` (R/core.R), the replacement counts built
from the trimmed mean and size/normalization factors are coerced with
`as.integer(...)`, which truncates toward zero:

```r
replacementCounts <- if (!is.null(normalizationFactors(object))) {
  as.integer(matrix(rep(trimBaseMean,ncol(object)),ncol=ncol(object)) *
             normalizationFactors(object))
} else {
  as.integer(outer(trimBaseMean, sizeFactors(object), "*"))
}
```

So every replaced outlier count is biased low by 0.5 on average (a trimmed-mean
prediction of 3.9 becomes 3). Since replacement happens only for samples in
cells with ≥ `minReplicatesForReplace` replicates and the values are refit
afterwards, the practical effect is small — but the bias is systematic and
one-directional, and the fix is one word (`round()` before coercion).

At typical bulk counts (hundreds) this is negligible; at low counts the
replaced sample sits visibly below its fitted mean, which slightly inflates the
post-replacement dispersion for exactly the genes that were flagged.

A PR with the one-line fix is available:
https://github.com/thelovelab/DESeq2/compare/devel...cindykrafft:deseq2:fix/replace-outliers-rounding
Output changes only for analyses where outlier replacement triggered, and only
in the last integer digit of the replacement counts.
