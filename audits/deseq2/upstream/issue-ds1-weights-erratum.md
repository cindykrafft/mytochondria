TITLE: Request: NEWS/erratum entry for the results(contrast=) weights misalignment fixed in abe5994 (affected releases 1.16.0–1.49.x)

**Summary.** Commit abe5994 (2025-08-18, "fix issue with contrast affecting lfcSE
when using weights") fixed a one-line bug in `getContrast()`: the weights matrix
was taken from the unsubset object while counts, dispersions and betas had
all-zero rows removed. Because `fitBeta()` does no row-count check, gene *i*'s
counts were silently paired with gene *(i + offset)*'s weights, where offset is
the number of all-zero genes earlier in the matrix.

As far as I can tell there is no NEWS entry or user-facing notice for this fix.
Since the affected code was in every release from **1.16.0 (April 2017) through
1.49.x**, and the failure is silent (wrong `lfcSE`, `stat` and `pvalue`, no
warning), I'd like to request:

1. a NEWS/changelog entry naming the affected versions and the conditions, and
2. (ideally) a note on the Bioconductor support site so users of the affected
   workflow can check their analyses. I have a draft I'm happy to contribute.

**Conditions (all three required):**
- observation weights in `assays(dds)[["weights"]]` — primarily the
  zinbwave/zero-inflation single-cell workflow, which the DESeq2 docs
  recommended in this period;
- results extracted with `results(dds, contrast=...)` via a path that reaches
  `getContrast()` (numeric or list contrast, or a character contrast where
  neither level is the reference) — `results(name=)` and reference-level
  character contrasts were never affected;
- at least one all-zero gene in the object (guaranteed in practice for
  single-cell data).

**Magnitude** (reproduction on shipped v1.42.1; script attached: 2,000 genes,
10% all-zero scattered, zinbwave-style weights, 4v4):
- `lfcSE` ratio (contrast path / name path, same coefficient): 0.42–2.54×;
  33.8% of genes off by >10%;
- 1.78% of p<0.05 significance calls flip between the two paths;
- worst per-gene p-value ratio 12.7×;
- controls: with no all-zero rows, or no weights, the two paths agree to 7e-16,
  isolating the misalignment as the mechanism.

**Reproduction:** `ds1_weights_misalignment.R` in
https://github.com/cindykrafft/research-software-audit/tree/main/audits/deseq2/verify
— runs on any affected release; prints the comparison and both controls.

Found during a source audit of DESeq2 against 886 papers that used it in six
high-impact journals 2021–2026. Thank you for DESeq2 — the audit's main outcome
was how well the default analysis chain held up; this was the one confirmed
defect, and you had already fixed it.
