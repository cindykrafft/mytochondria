TITLE: Docs/NEWS request: make the v1.44 change of the default lfcThreshold test more visible (p-values differ up to 2x across the version boundary)

**Summary.** In 1.43.2 (commit 0247fd7, first release v1.44.0, 2024) the default
`altHypothesis="greaterAbs"` test changed from the 2014 statistic
`min(1, 2*pnorm((|LFC|-T)/SE, lower=FALSE))` to the more powerful
`pnorm(-|LFC|+T, sd=SE) + pnorm(-|LFC|-T, sd=SE)`, with the old behavior
preserved as `greaterAbs2014`. Both are valid tests, and the new one is a real
improvement — this is not a bug report.

The request is visibility. In a survey of 886 papers using DESeq2 in six
high-impact journals (2021–2026), version pins span 1.18 through 1.44+, and
`lfcThreshold` users straddle the boundary. On identical data and an identical
call, the two versions produce (simulation, T=0.585, 5v5, half the genes with
true LFC near the threshold):

- p-values differing up to 2x (median ratio 1.22);
- +19% genes at padj < 0.05;
- 0.8% of tested genes changing significance status.

Someone reproducing a ≤1.42 paper on a current DESeq2 (or vice versa) will see
different gene lists and has essentially no way to discover why: the change is
not in NEWS under a searchable phrase, and `?results` describes the current
behavior only.

**Suggested (happy to send a docs PR for any of these):**
1. a NEWS entry under 1.44.0 explicitly saying "lfcThreshold p-values change;
   use `altHypothesis='greaterAbs2014'` to reproduce pre-1.44 results";
2. one sentence in `?results` under `altHypothesis` noting the boundary and the
   back-compatibility option;
3. mention in the vignette's lfcThreshold section.
