TITLE (Bioconductor support site): PSA: check DESeq2 analyses that combined observation weights (e.g. zinbwave) with results(contrast=) — versions 1.16–1.49

This is a heads-up for users of the **zinbwave + DESeq2** workflow (or any
analysis that put observation weights in `assays(dds)[["weights"]]`).

DESeq2 versions **1.16.0 (2017) through 1.49.x (2025)** contained a silent bug,
fixed in newer versions ([commit abe5994](https://github.com/thelovelab/DESeq2/commit/abe5994)):
when results were extracted with `results(dds, contrast=...)` (numeric or list
contrasts, or comparisons between two non-reference levels), the per-gene
weights were misaligned with the genes whenever the dataset contained all-zero
genes — which single-cell data always does. Standard errors, test statistics
and p-values from that call could be substantially wrong (in a realistic
simulation, a third of genes had `lfcSE` off by more than 10%, and ~2% of
significance calls flipped).

**You are NOT affected if any of these hold:**
- you never had weights in `assays(dds)` (bulk RNA-seq with the standard
  pipeline, tximport included, does not add weights);
- you used `results(dds, name=...)` or a contrast against the reference level
  (e.g. `contrast=c("condition","treated","untreated")` where untreated is the
  reference) — these paths were always correct;
- you filtered out all-zero genes before the results call and your object had
  none.

**To check an affected analysis:** re-run the same `results()` call under
DESeq2 ≥ 1.50 (or current release) and compare, or — on the old version —
relevel the factor so your comparison is against the reference and use
`results(name=)`; that path was always correct.
