### PR 1 — `fix/arrayweights-prwts-reml-convergence` — "arrayWeights(): fix the convergence criterion of the prior-weights REML fit"

Follows the support-site post #NNN.

`.arrayWeightsPrWtsREML()` divides its Fisher-scoring convergence criterion by
`ngenes+prior.n` a second time (the score and information are already per-gene averages),
so it is `ngenes+prior.n` times smaller than `.arrayWeightsREML()`'s for the same state and
the default `tol=1e-5` is met after one or two iterations. With a weight matrix of ones the
two routines fit the same model but returned weights up to 15 % apart (10,000 genes, 8
arrays); `voomWithQualityWeights(method="reml")` returned sample weights up to 12 % from
converged. The devel C backend `src/awreml.c` carries the same expression, and devel's
`voomLmFit(sample.weights=TRUE)` routes to it whenever no df are lost to exact zeros.

The change uses `num/ngam` (C) and `crossprod(dl,gamstep)/ngam` (R), the per-gene scale of
`.arrayWeightsREML()`, so the two routines agree to rounding on equal prior weights; it adds
`tests/arrayweights-reml.R` and changelog (and, on devel, NEWS) entries.

- Patches: `0001-arrayWeights-fix-the-convergence-criterion-of-the-pr.patch` (against
  `devel` @ `57a8de72`, `git am`-clean) and
  `0001-arrayWeights-fix-the-convergence-criterion.RELEASE_3_23.patch` (against
  `RELEASE_3_23` @ `825d1c83`; that branch stores CRLF line endings, so apply with
  `git am --keep-cr`).
- Tests: `tests/arrayweights-reml.R` fails on the unmodified code of both branches
  (`all.equal(w0, w1)` not TRUE) and passes with the patch; `R CMD BATCH --vanilla
  tests/limma-Tests.R` then `R CMD Rdiff` gives the same 76 pre-existing lines with and
  without the patch on both branches; the five devel `stopifnot` test files pass.
- Results change for every `arrayWeights(method="reml")` call with prior weights (and so for
  `voomWithQualityWeights(method="reml")` and devel's `voomLmFit(sample.weights=TRUE)`), so
  this is a results-affecting change and is offered through the support site first, per the
  project's channel.

### PR 2 — `fix/voom-offset-precedence` — "voom(): give an edgeR-style offset precedence over lib.size, as voomLmFit() does"

Follows the support-site post #NNN.

`voom()` (3.68.0 onwards) row-mean corrects an edgeR-style offset matrix and adds it to
`log(lib.size)`; an edgeR offset already contains the log library sizes, so the effective
library size became `lib.size^2/geomean(lib.size)`, `E` was shifted by
−log2(lib.size/geomean) per column and the group logFC by the log2 ratio of the groups'
library sizes. Devel's `voomLmFit()` already reads the same DGEList slot as `exp(offset)`
(NEWS 4.0.0), so the two functions disagreed on the same object.

The change makes `voom()` set the library sizes to `exp(offset)` when `offset` is given
(matrix or vector), ignore `offset.prior` in that case with a message, and keep the
`offset.prior` behaviour; it rewrites the `offset`/`offset.prior` items and the Details
paragraph of `man/voom.Rd` to match `man/voomLmFit.Rd`, and adds `tests/voom-offset.R`,
which checks that `offset = log(lib.size)` reproduces `lib.size=`, that a gene-specific
offset gives `log2((counts+0.5)/(exp(offset)+1)*1e6)`, and that `offset.prior` still adds to
`log(lib.size)`.

- Patch: `0002-voom-give-an-edgeR-style-offset-precedence-over-lib.size.patch` (against
  `devel` @ `57a8de72`, on top of the PR 1 patch; `git am`-clean). Not prepared for
  `RELEASE_3_23`: a semantics change belongs with the 4.0.0 `voomLmFit` change.
- Tests: `tests/voom-offset.R` fails on the unmodified devel code (`all.equal(v0$E, v1$E)`
  not TRUE) and passes with the patch; `R CMD Rdiff` on `tests/limma-Tests.R` unchanged
  (76 pre-existing lines); the five devel C test files pass.
- Results change only for `voom()` calls that receive an `offset` (argument or DGEList
  element); `offset.prior` users are unaffected. Offered as a semantics question through the
  support site, since the current behaviour is documented.
