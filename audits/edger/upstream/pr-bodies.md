### PR 1 — `fix/filterbyexpr-cpm-cutoff-tolerance` — "filterByExpr(): tolerate last-bit rounding at the CPM cutoff"

Follows the support-site post #NNN.

A gene with exactly `min.count` reads in the median-size library has CPM mathematically
equal to `CPM.Cutoff` and should count towards `MinSampleSize`, but `cpm()` computes
`y*1e6/lib.size` in C while the cutoff is `min.count/lib.size*1e6` in R, and the two
round to different last bits for about 12 % of library sizes (17 % with the pre-4.4 C++).
Such genes then fail `CPM >= CPM.Cutoff` by one ulp and are dropped although the
documented rule keeps them.

The change compares against `CPM.Cutoff*(1-tol)` with the `tol` the function already
uses for the sample-count comparison, and adds the boundary case to
`tests/edgeR-Tests.R` with its output in `edgeR-Tests.Rout.save`.

- Patches: `0001-filterByExpr-tolerate-last-bit-rounding-at-the-CPM-c.patch` (against
  `devel` @ `db4e697f`, `git am`-clean) and
  `0001-filterByExpr-tolerate-last-bit-rounding.RELEASE_3_23.patch` (against
  `RELEASE_3_23` @ `c4a54bda`; that branch stores CRLF line endings, so apply with
  `git am --keep-cr` or `git apply`).
- Tests: `R CMD BATCH --vanilla tests/edgeR-Tests.R` then `R CMD Rdiff` against the saved
  output: 0 lines with the patch on both branches; without it the new case prints
  `FALSE  TRUE` instead of `TRUE TRUE` (4 Rdiff lines) and nothing else changes.
- Results change only for genes exactly on the cutoff (about 0.2 % of genes in the
  simulations, 9 % of which flip), so this is a results-affecting change and is offered
  through the support site first, per the project's channel.
