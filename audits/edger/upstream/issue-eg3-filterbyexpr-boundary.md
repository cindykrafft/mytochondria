Title: filterByExpr(): a gene with exactly min.count reads in the median-size library can fail the CPM cutoff by one ulp

<!-- Bioconductor support site post (https://support.bioconductor.org, tag: edgeR). edgeR has no
     issue tracker; this is the channel named in vignettes/intro.Rmd. Attach the patch from this
     directory (0001-...RELEASE_3_23.patch for the release branch, the other for devel). -->

`filterByExpr()` documents its rule as keeping genes with `CPM >= CPM.cutoff` in
`MinSampleSize` samples, with `CPM.cutoff = min.count / median(lib.size) * 1e6`. With an
odd number of samples the median library size is one of the libraries, so a gene with
exactly `min.count` reads in that library has CPM mathematically equal to the cutoff and
should count. In the code the cutoff is `min.count/MedianLibSize*1e6` (R) while `cpm()`
computes `y*1e6/lib.size` (C), and the two round to different last bits for many library
sizes, so such a gene is sometimes dropped.

**Minimal example** (edgeR 4.10.5, R 4.3.3; identical on 4.0.16, 4.4.2, 4.10.1 and devel 4.99.4):

```r
library(edgeR)
y <- rbind(c(5, 10, 5), c(5, 11, 5))
lib.size <- c(1e6, 1000010, 3e6)                    # median library = sample 2
filterByExpr(y, group=c(1, 2, 1), lib.size=lib.size)   # MinSampleSize = 1, totals 20 and 21
#> [1] FALSE  TRUE
sprintf("%.17g", c(cpm(y, lib.size=lib.size)[1, 2], 10/median(lib.size)*1e6))
#> [1] "9.9999000009999897" "9.9999000009999914"
```

**Expected:** `TRUE TRUE` — gene 1 has 10 reads in the median library (CPM equal to the
cutoff, 9.99990000099999…), only one sample is required, and its total of 20 exceeds
`min.total.count`. **Got:** `FALSE` for gene 1; the same gene with 11 reads is kept.

**How often:** over 200,000 random library sizes between 1e5 and 8e7, a count of exactly
10 fails `cpm(...) >= 10/L*1e6` for 12.4 % of them (17.2 % with the C++ code of edgeR
4.0.x, which multiplies in the other order). In 40 simulated data sets with 5–11 samples
and 20,000 genes at the defaults, 148 of the 1,589 genes that sat exactly on the margin
(min.count reads in the median library and exactly MinSampleSize libraries at or above the
cutoff) were dropped; every disagreement between `filterByExpr()` and the documented rule
was such a gene. That is about 4 genes per data set — small, but it changes the retained
gene count and, through BH, the adjusted p-values slightly, and it depends on the binary
representation of the median library size rather than on the data.

Shrinking the example showed what it needs: an odd number of samples (with an even number
the median is an average and no library sits on it) and exactly `min.count` reads in the
median-size library; the group/design structure only sets `MinSampleSize`.

**Proposed fix** (patch attached; the same change applies to devel): compare with a
relative tolerance, reusing the `tol` the function already applies to the sample count,

```r
keep.CPM <- rowSums(CPM >= CPM.Cutoff*(1-tol)) >= (MinSampleSize - tol)
```

An alternative with the same effect is to compute the cutoff through `cpm()` itself
(`cpm(matrix(min.count,1,1), lib.size=MedianLibSize)`), so that both sides use the same
arithmetic. The patch adds the example above to `tests/edgeR-Tests.R` and its output to
`edgeR-Tests.Rout.save`; with it `R CMD Rdiff` against the saved output is empty on both
branches, and the new case fails (`FALSE TRUE`) on the unpatched code.
