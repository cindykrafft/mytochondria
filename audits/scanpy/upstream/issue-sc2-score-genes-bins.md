Title: BUG: `score_genes` expression bins are not `n_bins` equal-frequency bins; the top bin holds 1–12 genes (or none)

**What happened?**

**Expected:** with the default `n_bins=25`, `sc.tl.score_genes` puts genes into 25 equal-frequency expression bins (the docstring says it reproduces Seurat's approach, whose `AddModuleScore` uses `cut_number()`), so any gene list gets `ctrl_size=50` matched control genes from each bin it touches.

**Got** on `main` (`a656a33b`) and on 1.12.4, the latest release: a list of the nine most-expressed genes raises `RuntimeError: No control genes found in any cut` (script below; `ctrl_as_ref=False` raises the same). Five of those genes score with only 4 control genes.

**Why:** `_score_genes_bins` assigns bins with

```python
n_items = int(np.round(len(obs_avg) / (n_bins - 1)))
obs_cut = obs_avg.rank(method="min") // n_items
```

Ranks run 1..N, so bins `0 .. n_bins-2` hold `n_items` genes each and the last bin holds whatever is left, `N - (n_bins-1)*n_items + 1` genes. Shrinking the example showed this is the critical part: the top bin is degenerate whenever `(n_bins-1) * round(N/(n_bins-1)) <= N`, e.g. 9 genes for N = 2,000 or 20,000, a single gene for N = 18,000 or 30,000, and for N = 25,000 the rounding goes the other way and there are only 24 bins. So the top handful of expressed genes (in PBMC data: MALAT1, mitochondrial and ribosomal genes, B2M, TMSB4X, FTL/FTH1, which is what "stress", "housekeeping" or ribosomal signatures contain) never get a proper control set. Lists that avoid those genes are unaffected: their scores agree to three decimals with equal-frequency bins. The same two lines ship in 1.11.5, 1.9.1, 1.7.2 and 1.4.6.

**Proposed fix:**

```python
obs_cut = ((obs_avg.rank(method="first") - 1) * n_bins // len(obs_avg)).astype(int)
```

`n_bins` equal-frequency bins with ties broken by order, as `cut_number` does. Bin membership changes for the top ~4 % of genes, so seeded control draws (and `tests/_data/score_genes_reference_paul2015.pkl`, generated "using the same code") change; a regression test on bin sizes is included in the branch. PR follows.
