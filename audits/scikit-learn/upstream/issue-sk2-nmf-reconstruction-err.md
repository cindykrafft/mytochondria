**Describe the issue linked to the documentation**

`NMF` and `MiniBatchNMF` document `reconstruction_err_` as "Frobenius norm of the matrix difference, or beta-divergence, between the training data `X` and the reconstructed data `WH` from the fitted model". The attribute is computed by `_beta_divergence(X, W, H, beta_loss, square_root=True)`, which returns `sqrt(2 * D_beta(X, WH))` for every loss. For `beta_loss="frobenius"` that is the Frobenius norm, as documented; for `"kullback-leibler"` and `"itakura-saito"` it is the square root of twice the divergence, not the divergence:

```python
import numpy as np
from sklearn.decomposition import NMF

X = np.random.RandomState(0).rand(60, 20) * 10
nmf = NMF(n_components=4, beta_loss="kullback-leibler", solver="mu", max_iter=1000, random_state=0).fit(X)
WH = nmf.transform(X) @ nmf.components_
kl = np.sum(X * np.log(X / WH) - X + WH)
print(f"reconstruction_err_       = {nmf.reconstruction_err_:.6f}")
print(f"generalised KL divergence = {kl:.6f}")
print(f"sqrt(2 * KL divergence)   = {np.sqrt(2 * kl):.6f}")
```

```
reconstruction_err_       = 40.116869
generalised KL divergence = 804.557308
sqrt(2 * KL divergence)   = 40.113771
```

(1.9.1; the same wording and value on 1.1.3 through 1.5.2. The residual 3e-3 difference is `transform` re-solving `W`.) Anyone selecting `n_components` or `beta_loss` by comparing `reconstruction_err_` with a divergence they compute themselves, or reporting it as "the KL divergence of the fit", gets a quantity on a different scale.

**Suggest a potential alternative/fix**

State what the attribute is, in both classes:

> Distance between the training data `X` and the reconstructed data `WH` from the fitted model: the Frobenius norm of the difference for `beta_loss='frobenius'`, and the square root of twice the beta-divergence for the other losses (so that it reduces to the Frobenius norm for `beta_loss=2`).
