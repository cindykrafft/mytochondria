### PR 1 — `fix/pca-covariance-eigh-centering` — "FIX PCA covariance_eigh: accumulate the covariance of centered batches"

#### Reference Issues/PRs

Fixes #NNN (the SK1 issue). Related: #27491 (the solver), #29534 (a different `covariance_eigh`
stability report, rank-deficient data with `whiten=True`).

#### What does this implement/fix? Explain your changes.

`PCA._fit_full`'s `covariance_eigh` branch computed the covariance as `X.T @ X - n_samples * mean ⊗ mean`
(`_cov` in `sklearn/utils/_array_api.py`). When the features carry a common offset the two terms are
nearly equal and the variance is lost to cancellation: with unit-scale variation, float32 values
around 100 give an `explained_variance_` 33 % off, around 1e3 87 % off; float64 values around 1e6
are 1.7 % off, around 1e7 20 %, around 1e8 meaningless. `svd_solver="auto"` selects this solver for
dense data with at most 1000 features and at least ten times as many samples since 1.5, so users
get the loss without choosing the solver; the `full` solver is exact in every case.

The change accumulates `(X[batch] - mean_).T @ (X[batch] - mean_)` over row batches
(`gen_batches` with `get_chunk_n_rows`, as in `pairwise_distances_chunked`) for dense input. That
keeps the memory footprint of the post-hoc formula (no full centred copy of `X`; the batch is at
most the working-memory setting) and removes the cancellation. Sparse input keeps the post-hoc
centering, since it cannot be centred without densifying. Array API inputs go through the same
batched path (`X[batch] - mean_`, `X_batch.T @ X_batch`, `xp.zeros(..., device=array_device(X))`).

With the change every case above is within 5e-6 (float32) / 4e-10 (float64) of the offset-free fit,
matching `full`. `test_pca_covariance_eigh_large_offset` (float64 offsets 1e6 and 1e8, float32 offsets
1e2 and 1e3, 2000 × 5, `global_random_seed`) fails on `main` (all four cases) and passes with the
change for seeds 0, 1, 7 and 42; the whole `sklearn/decomposition/tests/test_pca.py` passes.
Changelog fragment in `doc/whats_new/upcoming_changes/sklearn.decomposition/`.

Not changed: the sparse path (still post-hoc, unchanged numbers), `IncrementalPCA` (centres its
batches already), the `auto` policy.

### PR 2 — `fix/nmf-reconstruction-err-docstring` — "DOC NMF: say what reconstruction_err_ is for non-Frobenius losses"

#### Reference Issues/PRs

Fixes #NNN (the SK2 documentation issue), or opened directly per the documentation template.

#### What does this implement/fix? Explain your changes.

`NMF.reconstruction_err_` and `MiniBatchNMF.reconstruction_err_` are documented as "Frobenius norm of
the matrix difference, or beta-divergence, between the training data `X` and the reconstructed data
`WH`". The attribute is `_beta_divergence(..., square_root=True)`, i.e. `sqrt(2 * D_beta(X, WH))`
for every loss: the Frobenius norm for `beta_loss='frobenius'`, but the square root of twice the
divergence for `'kullback-leibler'` and `'itakura-saito'` (40.1 for a KL divergence of 804.6 on a
60 × 20 example). Docstring only, both classes; no behaviour change, no changelog entry.
