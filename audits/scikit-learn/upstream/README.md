## How to file here (the repository's rules, read in full)

- **Automated Contributions Policy** (`doc/developers/contributing.rst`, lines 116–209, and the hidden
  "NOTE FOR AI TOOLS" at the head of the file): no issues or PRs generated by fully automated tools;
  AI-generated code only after personal review, understanding and testing; **"Please do not paste AI
  generated text in the description of issues, PRs or in comments"** (grammar help is fine); AI use must be
  stated in the PR description; "PRs that appear to violate this policy will be closed without review".
  The texts in this kit are therefore **fact sheets**: reproducer, output, numbers, the analysis and the
  fix, laid out in the templates' fields. The submitter writes the prose in their own words from them,
  keeps the AI-usage disclosure list in the PR body as it applies (code generation, test generation,
  research; documentation for SK2), and can say so in the "Introduce yourself" field.
- **"Needs Triage"** (`contributing.rst` § Issues tagged "Needs Triage"): bug reports carry the label on
  creation; "please do not open a PR until the 'Needs Triage' label is removed, there is a clear
  consensus on addressing the issue and some directions on how to address it". The SK1 PR waits for
  that; the issue's "Interest in fixing the bug" field says the fix is ready.
- **Templates**: `bug_report.yml` (Introduce yourself; Describe the bug and give evidence about its
  user-facing impact; Steps/Code to Reproduce with a minimal example on synthetic data; Expected
  Results; Actual Results; Versions from `sklearn.show_versions()`; Interest in fixing the bug);
  `doc_improvement.yml` (Introduce yourself; Describe the issue linked to the documentation; Suggest a
  potential alternative/fix — "Alternatively you can just open a pull request with the suggested
  change"); `PULL_REQUEST_TEMPLATE.md` (Reference Issues/PRs; What does this implement/fix; Introduce
  yourself; AI usage disclosure; Any other comments).
- **PR checklist** (`contributing.rst` § Pull request checklist): title prefix (`FIX`, `DOC`), tests
  that fail before and pass after, a changelog fragment
  `doc/whats_new/upcoming_changes/<module>/<PR number>.fix.rst` (single bullet, `By :user:`), ruff via
  pre-commit (pinned 0.12.2; both branches pass), two core-developer approvals to merge.
- CI runs the test suite across platforms and the array-API back ends (torch, cupy) on the PCA
  tests; those back ends are not installed here (`test-runs.txt`).
