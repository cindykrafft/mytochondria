Title: -x sr: AS:i is higher than the score of the reported alignment when a read ends in a mismatch (extension reaching the query end adds ez->max, not ez->mqe)

<!-- lh3/minimap2 has no issue template. First filing to this repository. Every version checked (2.17, 2.24, 2.26, 2.31). -->

**Versions:** 2.17-r941, 2.24-r1122, 2.26-r1175 and 2.31-r1302 (`master` @ 3c28777) behave the same.

With `-x sr`, a read with one mismatch in its last four bases at either end is aligned end to end (`150M`, `NM:i:1`), but `AS:i` is the score the alignment would have had if it had been clipped before the mismatch:

```
$ python3 x1_as_issue_repro.py     # 20 kb random reference; 150-bp reads, one mismatch d bp from the 3' end
$ minimap2 -ax sr ref.fa reads.fq | cut -f1,2,4,5,6,12-14
mm1_from_3p   0   6001   60   150M   NM:i:1   ms:i:298   AS:i:298
mm2_from_3p   0   7001   60   150M   NM:i:1   ms:i:296   AS:i:296
mm3_from_3p   0   8001   60   150M   NM:i:1   ms:i:294   AS:i:294
mm4_from_3p   0   9001   60   150M   NM:i:1   ms:i:292   AS:i:292
mm5_from_3p   0   10001  60   150M   NM:i:1   ms:i:290   AS:i:290
```

With `-A2 -B8`, 149 matches and one mismatch score 149×2 − 8 = 290 whatever the mismatch's position. The reported AS is 8, 6, 4 or 2 higher when the mismatch is 1, 2, 3 or 4 bp from the end. The 5' end behaves the same.

**Cause.** In `mm_align1()` (`align.c`), the left and right extensions run `ksw_extz2_sse`/`ksw_extd2_sse` with `KSW_EZ_EXTZ_ONLY` and `end_bonus` (10 under `-x sr`). When `ez->mqe + end_bonus > ez->max`, the extension sets `ez->reach_end` and backtracks from the query end (`ksw_backtrack(..., ez->mqe_t, qlen-1, ...)`). That path scores `ez->mqe`. `mm_align1` uses `reach_end` to set the coordinates, but it adds `ez->max` to `dp_score`, which becomes `AS:i`:

```c
// align.c:792-797 (left; the right extension at 884-889 is the same)
if (ez->n_cigar > 0) {
    mm_append_cigar(r, ez->n_cigar, ez->cigar);
    r->p->dp_score += ez->max;                       // score of the clipped path
}
rs1 = rs - (ez->reach_end? ez->mqe_t + 1 : ez->max_t + 1);   // coordinates of the end-to-end path
```

`ez->max` is the best score anywhere in the extension, so AS includes a clipped path's score while CIGAR, NM and MD describe the end-to-end one. The default long-read presets use `end_bonus = -1`, where `reach_end` cannot be set, so they are unaffected. In our checks, AS matched the CIGAR for map-ont and splice.

**How often.** We recomputed every primary record's AS from its own CIGAR using the manual's scoring (match +A, mismatch −B, N −1, a gap of length k costing min{O1+k·E1, O2+k·E2}). Dataset: 20,000 simulated 2 × 150 bp pairs, fragments N(350, 50), a sample genome carrying SNPs and small indels against a 2 Mb reference, and substitution errors rising from 0.1 % at the 5' end to 1.5 % at the 3' end. Result: 2,803 of 40,000 primary records (7.0 %) have AS above the CIGAR's score, by 2 (650), 4 (685), 6 (704), 8 (758), or 10–16 when both ends are affected (6). The counts are identical on 2.17, 2.24, 2.26 and 2.31.

This matters wherever AS is compared or thresholded, for example in AS-based filters or in assigning reads between two references by AS. Reads with a terminal mismatch score up to 8 points higher (16 if both ends) than reads with the same mismatch in the interior.

**Fix.** Add the score of the path that was reported:

```c
r->p->dp_score += ez->reach_end? ez->mqe : ez->max;
```

at both places. On the data above, AS then equals the CIGAR-derived score on 40,000/40,000 records, and nothing else in the SAM changes: FLAG, POS, MAPQ, CIGAR, TLEN, and NM/ms/s1/s2/de are identical on all 40,000 records. MAPQ and pairing use `dp_max`, which `mm_update_extra()` recomputes from the CIGAR. The README examples on `test/` give identical output. PR follows.
