### PR 1 — `fix/as-end-to-end-extension` — "Score extensions that reach the query end by the end-to-end path"

Fixes #NNN.

When the left or right extension in `mm_align1()` reaches the end of the query (`ez->reach_end`, which happens whenever the end bonus is positive, as under `-x sr`), the CIGAR is backtracked from the query end and that path scores `ez->mqe`. `dp_score` was incremented by `ez->max`, the best score anywhere in the extension, so `AS:i` described a clipped alignment while the CIGAR, NM and MD described the end-to-end one. A 150-bp read with one mismatch 1, 2, 3 or 4 bp from either end got `AS:i:298/296/294/292` for `150M NM:i:1`, where the scoring gives 290.

This adds `ez->mqe` in that case, at both extensions (two lines in `align.c`). On 20,000 simulated 2 × 150 bp Illumina-like pairs under `-x sr`, AS changes on 2,803 of 40,000 primary records (7.0 %), each to the score recomputed from its own CIGAR. No other field changes: FLAG, POS, MAPQ, CIGAR, TLEN, NM, ms, s1, s2 and de are identical, because MAPQ and pairing use `dp_max`, which `mm_update_extra()` recomputes from the CIGAR. Presets with the default `end_bonus = -1` (map-ont, splice, asm*) are untouched: AS was already consistent there, and the README examples on `test/` give byte-identical output. Builds cleanly with gcc 13 and clang on x86_64; the only gcc warnings are the existing `fread` ones in `index.c`.
