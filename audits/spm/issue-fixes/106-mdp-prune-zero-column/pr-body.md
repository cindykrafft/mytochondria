Title: Guard spm_MDP_VB_prune against columns left with no prior mass

Fixes #106.

**Cause.** `spm_MDP_VB_prune` rescales the reduced prior column by column to preserve the prior probability mass, `rA = rA .* (sum(pA)./sum(rA))`. When a column of `rA` is left with no mass — a prior column of zeros (a state the prior has never visited while the posterior has accumulated counts there), or `SIMPLE`-mode pruning that removes every entry carrying prior mass — this is `0/0` (or `0*Inf`) and the whole column becomes `NaN`. The `NaN` column then goes through `spm_MDP_log_evidence` and is written back into the returned priors, so the next learning epoch (e.g. the `spm_RDP_update` loop of `DEM_demo_MDP_video`) starts from a corrupted model; depending on the MATLAB version this surfaces as the `spm_betaln` error in the report or as silent `NaN`s. The default `MI` mode has the same `0/0` for an all-zero prior column.

**Fix.** Move the mass-preservation step out of the `MI`/`SIMPLE` switch, detect columns with no reduced mass, leave them unreduced (`rA = pA`, so the reduced free energy is exactly zero and `qA`/`pA` are unchanged for those columns) and set their rescaling factor to one. Columns that do carry mass are handled exactly as before, so the reference reduction is unchanged. This is the guard suggested in the issue, extended so that an all-zero prior column (where `sum(pA)` is itself zero) does not fall into a second `0/0`.

**Test.** `tests/test_spm_MDP_VB_prune.m` (matlab.unittest, same layout as `test_spm_Ncdf.m`) checks the reference reduction of a healthy column (`[64;1]` with prior `[1;1]` → `[65;0]`, `[2;0]`), the two zero-mass cases in `SIMPLE` mode, the default `MI` mode with a zero prior column, and a 3-D tensor. On the current `main` 11 of its 23 assertions fail (every `NaN` and every "column left unchanged" check); with the fix 0 fail.

**What was run.** The assertions were executed with the real code under GNU Octave 8.4 (with a one-line shim for `sum(x,'all')`, which Octave lacks) against `main` (`4e20e07`) and against this branch, before and after.
