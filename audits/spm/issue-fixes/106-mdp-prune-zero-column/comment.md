The pruning mask cannot empty a column by itself (its maximum is always above `-log(32)`, and `spm_psi` clips at −32). What does make `sum(rA)` zero is a column whose surviving entries carry no prior mass: an all-zero prior column for a state the prior has never visited, which is the usual situation inside the `spm_RDP_update` loop, or pruning that removes exactly the entries where `pA > 0`. The rescale `rA = times(rA, sum(pA)./sum(rA))` is then `Inf` or `0/0`, the whole column of `rA` becomes NaN, and although the `max(z, exp(-32))` clamp in `spm_betaln` now swallows the NaN (so under Octave there is no error, only a silent NaN), the NaN column is written back into the returned prior and, in SIMPLE mode, the posterior column is zeroed. The default MI branch has the same `0/0` for an all-zero prior column.

The branch leaves such columns unchanged (`rA = pA`, rescale factor 1, so `F = 0` and neither the Occam's-window nor the BMA branch touches them) in both modes, and adds `tests/test_spm_MDP_VB_prune.m` (23 assertions; 11 fail on `main`, 0 with the change). Reproduction with a 2×2 case: `spm_MDP_VB_prune([64;1],[0;1],0,0,[],'SIMPLE')` returns `rA = [NaN;NaN]`, `sA = [0;0]` on `main`.
