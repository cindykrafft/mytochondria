Yes, that matches what we found: `poisson_cdf(n, lam, lower=False)` is R's `ppois(n, lam, lower.tail = FALSE)`, which is P(X > n). The one subtlety is that the "at least as extreme" p-value for an observed count n is P(X ≥ n), i.e. `ppois(n - 1, lam, lower.tail = FALSE)`. So a user who computes the textbook p-value from the pileup and lambda gets a value larger than MACS's by the probability of exactly n: about 4 to 14 times larger at the default cutoff for local lambda between 0.5 and 5.

Nothing needs to change in the code. Would a short note in the docs be welcome? I'd add one sentence under `-p/--pvalue` in `callpeak.md` and one under `ppois` in `bdgcmp.md`, e.g.:

> The Poisson p-value for a pileup of n reads with expected count λ is P(X > n), computed as R's `ppois(n, λ, lower.tail = FALSE)`; the standard "at least n" tail P(X ≥ n) is `ppois(n - 1, λ, lower.tail = FALSE)`.

I'm happy to send it as a docs PR, or to close this issue if you'd rather leave the docs as they are.
