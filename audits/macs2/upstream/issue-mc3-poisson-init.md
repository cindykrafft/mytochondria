TITLE: __poisson_cdf_large_lambda drops the k=0 term (was summed from uninitialized memory in the MACS2 2.x releases)

**Summary.** In `MACS3/Signal/Prob.py`, `__poisson_cdf_large_lambda`
accumulates the lower-tail CDF in a loop starting at i=1; the i=0 term is
never added. The lineage makes the intent clear:

- **MACS 1.4** (`lib/Prob.py`): `next = EXPSTEP; cdf = next` — correct, the
  i=0 term seeds the sum;
- **MACS2 2.x** (`Prob.pyx`, e.g. 2.2.7.1 lines 261–301): the `cdf = next`
  line was lost in the Cython port, and `cdf` is a `cdef double` that is
  **read uninitialized** (`cdf = cdf + nextcdf` on the first iteration sums
  C stack garbage);
- **current MACS3**: `cdf: float64_t = 0` removed the undefined behavior but
  still omits the first term.

**Practical impact: none today.** The function asserts λ > 700, where the
scaled exp(−λ) first term is negligible against the sum, and no current CLI
path reaches it (peak calling uses the log-space branch; `poisson_cdf_inv`
has its own loop). It is a latent landmine for any future caller — and in the
2.x releases, formally undefined behavior.

A one-line PR restoring the MACS 1.4 initialization follows.
