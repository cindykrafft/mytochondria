Title: max|grad| convergence warning always reports "component 1"

<!-- lme4 has no issue template; free-form report. Message text only, no number in a fit changes. -->

**Summary.** `checkConv()` builds the "Model failed to converge with max|grad| = ... (tol = ..., component %d)" warning from `which.max(maxmingrad)` (`R/checkConv.R:86`), but `maxmingrad` is already the scalar `max(mingrad)` (`:84`), so the component is always 1 whichever gradient component is largest. Present on 1.1-35.1, 2.0-6 and `master` @ 69588fa.

**Expected:** the index of the parameter whose gradient triggered the warning. **Got:** always 1.

**Minimal reproducible example**

```r
library(lme4)
ctrl <- lmerControl()$checkConv
derivs <- list(gradient = c(1e-6, 0.5, 1e-6), Hessian = diag(3))      # the gradient is large in component 2 only
lme4:::checkConv(derivs, coefs = c(1, 1, 1), ctrl = ctrl, lbound = c(0, 0, 0))
```

```
Warning message:
In lme4:::checkConv(derivs, coefs = c(1, 1, 1), ctrl = ctrl, lbound = c(0,  :
  Model failed to converge with max|grad| = 0.5 (tol = 0.002, component 1)
```

On a real fit (`sleepstudy`, `theta` perturbed so that the second component carries a gradient of 53) the warning also says component 1. Shrinking the example showed that only the warning text is affected: the returned `code` (-1) and every other message are right.

**Fix:** `w <- which.max(mingrad)`. A branch with the one-token change, a test (`test-checkConv.R`) and a NEWS entry is ready; PR to follow if wanted.
