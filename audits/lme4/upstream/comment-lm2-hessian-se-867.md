Title: (comment on #867 "revisit use.hess default") a failure-rate measurement for the default Hessian-based SEs, and a cheap guard

Some numbers that may help with the "can we do better?" question, all from ordinary, well-specified Bernoulli random-intercept fits (`glmer(y ~ x + (1|g), family = binomial)`, 10 observations per cluster, sd(RE) = 1.2, beta = (-0.5, 1)); identical on 1.1-35.1, 2.0-6 and `master` @ 69588fa.

The nine bad fits (6 % of 150) print an intercept SE of 0.0005-0.0026 where RX gives 0.07-0.34, i.e. |z| of 198-978 instead of 1.7-7.4, and every one of them came with "Model failed to converge with max|grad| = 0.027-0.13 (tol = 0.002, component 1)" and nothing else; `?convergence` tells users that check is often too conservative. When the Hessian is sound it is the better estimator: in a 300-replicate Monte Carlo with sparse clusters (30 x 4, sd(RE) = 2) the sampling SD of beta-hat is 0.486/0.368, the mean Hessian SE 0.456/0.337 and the mean RX SE 0.432/0.302 (median Hessian/RX difference 5 %/11 %). The mismatch check in `vcov.merMod` (`R/lmer.R:2282-2291`) only runs when `use.hessian = FALSE` is given explicitly, so nothing flags the default path (#994).

Minimal example (any seed that raises the max|grad| warning tends to reproduce it; this one does on all three versions):

```r
library(lme4)
set.seed(6)
J <- 20; nj <- 10
g <- gl(J, nj); x <- rnorm(J * nj); b <- rnorm(J, sd = 1.2)
y <- rbinom(J * nj, 1, plogis(-0.5 + x + b[g]))
fit <- glmer(y ~ x + (1 | g), family = binomial)          # warns: max|grad| = 0.0219 (tol = 0.002)
print(coef(summary(fit)), digits = 4)                       # what a user sees
se <- rbind(default = sqrt(diag(as.matrix(vcov(fit)))),
            RX = sqrt(diag(as.matrix(suppressWarnings(vcov(fit, use.hessian = FALSE))))))
print(se, digits = 4)
```

A cheap guard that keeps the Hessian default but catches these: on the default path compare the SEs implied by the two matrices and fall back to RX, with a warning, when any differ by more than a factor of 2 (`getOption("lme4.vcov.hess.se.ratio")`, `Inf` to disable). On the 150 fits above it triggers exactly on the nine bad ones and on none of the others; on the example it prints the RX line ("... differ from the RX-based ones by a factor of up to 105: falling back to var-cov estimated from RX"). An alternative with the same effect on these data would be to fall back whenever `checkConv` returned a negative code. I have a branch with the guard, a test (`test-vcov-fallback.R`) and a NEWS entry; happy to open a PR if either variant is what you would want.
