The two counts come from the same scan: `merge_bim_scan()` reports the number of *records*
in the fileset it just read, while the base fileset's count is the number of *distinct*
variant IDs accumulated in the merge hash table, so a fileset with duplicate IDs is
described one way as the base ("27 markers loaded from Normed.bim") and another as the
second fileset ("29 markers to be merged from Normed.bim") — and `Of these, ... are present
in the base dataset` can then exceed the base dataset's own variant count. The duplicate-ID
warning added in 2 May 2020 only fires for the first fileset (the todo in the comment at
that site), so when the fileset with the duplicates is the second one there is no warning
at all.

duplicate *within* the current fileset is distinguishable from an ID shared with an earlier
fileset; the warning then names whichever fileset has duplicates, and the second fileset is
counted by distinct IDs. Genotype output is unchanged. PR #NNN attached, with a new
