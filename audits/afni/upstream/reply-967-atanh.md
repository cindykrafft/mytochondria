Thanks for laying the options out. Of the four I would take ±13, for two reasons:

- It is what `3dcalc`'s own `cdf` function and the `cdf` program already return for r = ±1, so the two routes to a Fisher z inside the same program agree.
- It keeps `atanh` monotone for every value a float dataset can hold without changing any |r| < 1: the largest float below 1 gives atanh ≈ 8.7, so nothing in range crosses the boundary value.

±4 would need the same early clamp `3dTcorrelate` uses (|r| ≥ 0.999329 → ±4) to stay monotone, which changes values for |r| > 0.99933 as well; reasonable for a correlation program, a stronger assumption for a calculator. Zero puts holes exactly where the effect is strongest, and ±1 keeps the non-monotone step (atanh(0.9999) = 4.95, "atanh(1)" = 1).

Two small things to fold into the same change whichever value you pick: apply it for |x| > 1 too (today `atanh(1.5)` returns 1.5, so an out-of-range input comes back looking like a valid z), and give the neighbouring cases their boundary value the same way (`acosh(x)` → 0 for x < 1; `asin`/`acos` with |x| > 1 → ±π/2 and 0/π).
