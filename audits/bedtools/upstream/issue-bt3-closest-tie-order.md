Title: closest -t first / -t last pick the wrong tie under -D a / -D b

**bedtools version:** master @ 614e9a5; reproduced on v2.31.1 and v2.30.0.

**What happened.** The docs define `-t first` as "the first tie that occurred in
the B file" and `-t last` as the last. When a query is equidistant from one B
record on its left and one on its right, `-t first`/`-t last` instead pick by the
`-D` orientation ("upstream" first), which is not file order under `-D a` or
`-D b`.

**Minimal reproduction:**

```bash
printf 'chr1\t10\t20\ta1\t1\t-\n' > a.bed
printf 'chr1\t5\t6\tb1\t1\t+\nchr1\t24\t25\tb2\t1\t+\n' > b.bed   # b1 and b2 both at distance 5

bedtools closest -a a.bed -b b.bed -d      -t first   # -> b1  (file order, correct)
bedtools closest -a a.bed -b b.bed -D ref  -t first   # -> b1
bedtools closest -a a.bed -b b.bed -D a    -t first   # -> b2  (expected b1)
bedtools closest -a a.bed -b b.bed -D a    -t last    # -> b1  (expected b2)
bedtools closest -a a.bed -b b.bed -D b    -t first   # -> b2  (expected b1)
```

**What shrinking the example showed.** Only ties that straddle the query are
affected, and only under a signed-distance mode where the right-hand record is
"upstream": `-D a` with a reverse-strand query, or `-D b` with a forward-strand
hit. Over 2000 queries each with one tied record on each side, `-D a -t first`
returned the non-first record for 1027/2000 (all reverse-strand queries) and
`-D b -t first` for 469/2000; `-D ref` and `-d` were always correct. The
reported distance is right and `-t all` is unaffected — only *which* single
record is reported is wrong.

**Cause.** `CloseSweep::finalizeSelections` (src/utils/NewChromsweep/CloseSweep.cpp:388-411)
resolves a tie by taking the upstream list first (unless `-t last`) and the
downstream list otherwise, where up/downstream is the `-D` sign, not the B-file
position. Choosing the tie by original file order would need the record's file
index carried through `RecDistList`; happy to work up that patch if you agree
this should match the documented "first/last in the B file" rule.
