### PR 1 — `fix/coverage-split-hit-count` — "coverage: count database records, not blocks, with -split and honour -f/-F"

Fixes #NNN (see also #673).

With `-split`, `CoverageFile::checkSplits` replaces the hit list by the list of
per-block overlaps the depth is computed from, so the count column (and
`-counts`) reported the number of overlapping blocks instead of database records:
a three-block read counted as 3, while `intersect -c -split` counts it once. The
per-block list was also kept when `BlockMgr::findBlockedOverlaps` had rejected
every hit under `-f`/`-F`/`-r`, so those options had no effect on
`coverage -split`.

This keeps the number of records that survived the fraction test as the hit
count and drops the per-block overlaps when none survived. `test/coverage/`
t10/t10b now expect a count of 1 for the three-block read (this is the
number-changing part — please confirm you want it); t10c–t10g add `-f 0.6`/`0.7`
with `-split` and a two-block BED12 record. Full `make test` passes.

### PR 2 — `fix/intersect-split-per-record-F` — "intersect: apply -F and -r to each database record under -split"

Fixes #1142.

`BlockMgr::findBlockedOverlaps` tested `-F` (and `-r`'s reciprocal test) against
the summed block length of every database record that touched the query, with the
non-redundant overlap as numerator, and cleared every hit when that ratio was too
small. A record entirely inside the query was dropped once a neighbour also
overlapped it (three identical reads inside a 100-bp interval: 0 lines under
`-split -F 0.5`, 3 without `-split`); a record failing on its own was kept when a
neighbour passed. Without `-split` both options are per record.

This tests `-F`/`-r` per database record on that record's own block length and
keeps only the records that pass; `-f` remains the cumulative fraction of the
query covered by the survivors (issue #750). `test/intersect/` t22.p (`-F 0.20`)
gains one line (the two-block read qualifies on exon2 at 20/100); new t22.s/t22.t
cover three identical reads (`-F 0.5`, `-F 1.0`) and the #1142 isoform example.
Full `make test` passes.

### PR 3 — `fix/large-chrom-int-truncation` — "reldist, subtract, flank: keep 64-bit coordinates (large chromosomes)"

Fixes #NNN.

Coordinates are 64-bit (`CHRPOS`) since 2.28, but `reldist`, `subtract` and
`flank` narrowed them to 32-bit `int`, so on chromosomes with coordinates above
2^31 (~2.15 Gb): `reldist` cast the midpoint to int and silently dropped queries;
`subtract` produced negative end coordinates; `flank` collapsed the flanks. This
uses `CHRPOS` through those three code paths, with a large-chromosome test added
to each tool (failing on unmodified master). Full `make test` passes.

The related `closest -d`/`-k` truncation (`RecDistList` stores distances as
`int`) is not in this PR — it needs the container's index type widened — and is
noted in the issue.
