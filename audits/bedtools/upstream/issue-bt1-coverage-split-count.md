Title: coverage -split counts overlapping blocks, not database records, and ignores -f/-F

_bedtools has no issue template; this follows the usual bug-report shape (version,
command, input, output produced, output expected)._

**bedtools version:** master @ 614e9a5 (2026-06-10); reproduced identically on the
v2.31.1 and v2.30.0 release tags. Built with `make`, Linux x86-64, GCC.

**What happened.** With `-split`, `bedtools coverage` reports the number of
overlapping *blocks* in the "number of features in B that overlapped A" column
(and under `-counts`), not the number of database records, so a single spliced
read with N exons overlapping the A interval is counted N times. `bedtools
intersect -c -split` counts the same read once. Separately, `-f`/`-F` have no
effect on `coverage -split`: a database feature covering 10 % of A is still
reported (with its depth) under `-f 0.5`.

**Minimal reproduction** (synthetic data made in the script; output pasted from a
run on master):

```bash
# one BED12 read with two 100-bp blocks, both inside the A interval
printf 'chr1\t100\t1000\tgene\n' > a.bed
printf 'chr1\t150\t900\tread\t0\t+\t150\t900\t0\t2\t100,100\t0,650\n' > b.bed12

bedtools coverage -a a.bed -b b.bed12 -split
# got:      chr1  100  1000  gene  2  200  900  0.2222222
# expected: chr1  100  1000  gene  1  200  900  0.2222222   (one B record)
bedtools intersect -a a.bed -b b.bed12 -split -c
# chr1  100  1000  gene  1     <- one record, as coverage should also report

# -f is ignored under -split: a 10 % read is still counted
printf 'chr1\t100\t200\tgene\n' > a2.bed
printf 'chr1\t120\t130\tr\t0\t+\t120\t130\t0\t1\t10\t0\n' > b2.bed12
bedtools coverage -a a2.bed -b b2.bed12 -split -f 0.5
# got:      chr1  100  200  gene  1  10  100  0.1000000
# expected: chr1  100  200  gene  0   0  100  0.0000000
bedtools intersect -a a2.bed -b b2.bed12 -split -c -f 0.5
# chr1  100  200  gene  0
```

**What shrinking the example showed.** The bases-covered and fraction columns are
correct; only the *count* is wrong, and it equals the number of overlapping
blocks. Over 3000 random BED12 reads (1–4 blocks) against 300 A intervals the
count matches the block count for 300/300 A intervals and the record count for
102/300; `coverage -split -f 0.5` is byte-identical to `coverage -split` with no
`-f`. This is the same defect as #673 (open since 2018, `-split -f 1.0 -counts`
returning 444 instead of 30), now also covering the default count column and `-f`.

**Cause.** `CoverageFile::checkSplits` (src/coverageFile/coverageFile.cpp:236-247)
swaps the hit list for the per-block overlap list that the depth is computed from,
and `makeDepthCount` does `_hitCount++` once per element (:124-136). The per-block
list is kept even when `BlockMgr::findBlockedOverlaps` cleared the fraction-filtered
`resultSet`, so `-f`/`-F` never take effect.

**Fix.** Report the number of database records that survived the fraction test
(`resultSet.size()`) as the count, and drop the per-block overlaps when none
survived. Patch with tests attached (a PR follows once you confirm you want the
count-column semantics changed — `test/coverage/test-coverage.sh` t10 currently
asserts a count of 3 for a three-block read, which would become 1).
