Title: reldist, subtract, flank and closest -d truncate coordinates to 32-bit int on chromosomes > 2^31 bp

**bedtools version:** master @ 614e9a5; reproduced on v2.31.1 and v2.30.0.

**What happened.** Coordinates have been 64-bit (`CHRPOS`) since 2.28, but four
tools narrow them to 32-bit `int`, so on a chromosome longer than 2^31 bp
(~2.15 Gb — wheat, maize, axolotl, lungfish, many plant and amphibian genomes)
they silently produce wrong output. All examples use a 5-Gb chromosome:

```bash
printf 'chr1\t5000000000\n' > big.genome

# reldist: query silently dropped once start+end >= 2^31
printf 'chr1\t2999999900\t3000000100\nchr1\t3000000900\t3000001100\n' > b.bed
printf 'chr1\t3000000050\t3000000150\n' > a.bed
bedtools reldist -a a.bed -b b.bed -detail
# got: (no output)     expected: chr1  3000000050  3000000150  0.100

# subtract: negative end coordinate
printf 'chr1\t3000000000\t3000000100\n' > a.bed
printf 'chr1\t3000000010\t3000000020\n' > b.bed
bedtools subtract -a a.bed -b b.bed
# got:      chr1  3000000000  -1294967286   (and a second garbage line)
# expected: chr1  3000000000   3000000010
#           chr1  3000000020   3000000100

# flank: single garbage flank
printf 'chr1\t3000000000\t3000000100\n' > a.bed
bedtools flank -i a.bed -g big.genome -l 10 -r 10
# got:      chr1  0  3000000000
# expected: chr1  2999999990  3000000000
#           chr1  3000000100   3000000110

# closest -d: wrong distance (and -k reorders)
printf 'chr1\t0\t10\n' > a.bed
printf 'chr1\t3000000010\t3000000020\n' > b.bed
bedtools closest -a a.bed -b b.bed -d
# got: ... 1294967295     expected: ... 3000000001
```

**What shrinking the example showed.** The threshold is exactly 2^31: reldist
fails when a B record's `start + end >= 2147483648` (its midpoint cast to int
overflows); subtract/flank/closest fail when a coordinate or gap crosses 2^31.
The same tools are correct below 2^31, and tools that use `CHRPOS` throughout
(`intersect`, `coverage`, `merge`, `cluster`, `slop`, `window`) are correct at
3e9 — so this is per-tool int narrowing, not a genome-file limit.

**Cause.** `reldist.cpp:44,109` `(int)(bed.end+bed.start)/2`; `subtractFile.cpp`
holds keyStart/keyEnd/hitStart/hitEnd and block coordinates as `int`;
`flankBed.cpp` uses `int chromSize`/`int` flanks and `static_cast<int>`;
`CloseSweep` stores distances as `int` in `RecDistList`.

**Fix.** Use `CHRPOS` through reldist, subtract and flank — patch with a
large-chromosome test for each attached. The `closest -d`/`-k` fix needs
`RecDistList`'s distance type widened and is not in this patch; flagged here so it
can be tracked.
