Title: flank: with -s, treat records without a "-" strand as forward instead of dropping them

Fixes #1123.

`bedtools flank -s` only handled records whose column-6 strand was exactly `+` or `-`. Anything else — a BED3/BED4/BED5 file with no strand column, or a `.` strand — matched neither branch of the `if / else if` in `BedFlank::FlankBed()` (`src/flankBed/flankBed.cpp`) and was silently omitted, so a strand-less input produced **no output at all** under `-s`, which is the symptom in #1123 (and in the closed #1057). Without `-s` the same records are flanked normally.

Only a `-` strand needs the flanks swapped, so this change mirrors what `slop -s` already does (`BedSlop::AddSlop`: `should_swap = _forceStrand && bed.strand == "-"`): a `-` record goes through `AddStrandedFlank()`, every other record through `AddFlank()`. Output for `+`/`-` records is unchanged.

Before / after on master (`chr1 100 200` in a BED3 file, `-l 5 -r 0 -s`):

```
$ bedtools flank -i bed3.bed -g my.genome -l 5 -r 0 -s     # before: nothing
$ bedtools flank -i bed3.bed -g my.genome -l 5 -r 0 -s     # after
chr1	95	100
```

Changes:
- `src/flankBed/flankBed.cpp`: the dispatch on `-s` (one condition).
- `docs/content/tools/flank.rst`: one sentence on how `-s` treats features without a `-` strand.
- `test/flank/test-flank.sh`: `flank.t12`–`t14` (BED3 with `-l/-r` and `-b`; a file mixing `.` and `-` strands), with the two small input files `test/flank/nostrand.bed` and `test/flank/dotstrand.bed`. The three tests fail on unmodified master and pass with this change.

Run: `make -j8 && make test` — all tool suites pass (only `negativecontrol` fails, as intended).
