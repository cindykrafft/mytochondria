**Implementation.** `FilteredEntryNavigableMap.entrySet()` returns `filteredDelegate.entrySet()` ([Maps.java#L3290-L3293](https://github.com/google/guava/blob/79152348ece2de85559eb2eb18133862d492c892/guava/src/com/google/common/collect/Maps.java#L3290-L3293)). `filteredDelegate` is a `FilteredEntryMap` over the same backing map and predicate ([#L3212](https://github.com/google/guava/blob/79152348ece2de85559eb2eb18133862d492c892/guava/src/com/google/common/collect/Maps.java#L3212)). The `EntrySet` iterator there wraps each backing entry in a `ForwardingMapEntry`, and its `setValue` does `checkArgument(apply(getKey(), newValue))` and then writes through to the backing entry ([#L2998-L3025](https://github.com/google/guava/blob/79152348ece2de85559eb2eb18133862d492c892/guava/src/com/google/common/collect/Maps.java#L2998-L3025)). This PR doesn't touch that path. It only changes `entryIterator()`/`descendingEntryIterator()` and the two poll methods. In `FilteredEntryNavigableMap`, `entryIterator()`/`descendingEntryIterator()` back the navigation methods in `AbstractNavigableMap`. That's because `entrySet()`, `navigableKeySet()`, `values()` and `descendingMap()` are all overridden there, and `headMap`/`tailMap`/`subMap` return new filtered views.

**Tests.** As far as I can find:
- `MapsCollectionTest.filterNavigableMapSuite()` runs the testlib `NavigableMap` suites on `filterKeys`/`filterValues`/`filterEntries` over a `SafeTreeMap` with `MapFeature.GENERAL_PURPOSE`, which implies `SUPPORTS_PUT` ([MapsCollectionTest.java#L517-L568](https://github.com/google/guava/blob/79152348ece2de85559eb2eb18133862d492c892/guava-tests/test/com/google/common/collect/MapsCollectionTest.java#L517-L568)). So `MapEntrySetTester.testSetValue` and its null-value variants run on those maps' `entrySet()`, including on the sub-map and descending derived suites. They check that `setValue` returns the old value and that the new value shows up in the map. On this branch `MapsCollectionTest` passes (235,865 tests, 0 failures).
- The `IllegalArgumentException` for a value that fails the predicate is tested in `AbstractFilteredMapTest.testFilteredValuesIllegalSetValue` ([#L112-L123](https://github.com/google/guava/blob/79152348ece2de85559eb2eb18133862d492c892/guava-tests/test/com/google/common/collect/AbstractFilteredMapTest.java#L112-L123)). But its subclasses are `FilteredMapTest`, `FilteredBiMapTest` and `FilteredSortedMapTest`, and I didn't find one for `NavigableMap`. For the navigable case, the only check I know of is the one this PR adds at the end of `MapsTest.testFilteredNavigableMapNavigationEntriesAreSnapshots` ([MapsTest.java#L1467-L1471](https://github.com/cindykrafft/guava/blob/64248f2cc0ed486b651f90019cb8a7174badecbd/guava-tests/test/com/google/common/collect/MapsTest.java#L1467-L1471)). It asserts that an entry from `filtered.entrySet().iterator()` rejects a value failing the predicate, and that a valid `setValue` writes through to the backing `TreeMap`.
