You're right, thanks. The comment doesn't say "without a lookup"; that was my wording and I shouldn't have put it that way. I agree that `300.1.1.1` and `zz:1` are not valid host names.

What I was pointing at is narrower. In JDK 21, `getByName` calls `getAllByName`, which only tries literal parsing for strings starting with a hex digit or `:` (after stripping `[...]`), at `InetAddress.java` lines 1623–1636. `zz:1` doesn't start with either, so it goes straight to `getAllByName0`, the name lookup, at line 1688. `300.1.1.1` does start with a hex digit. But it is neither a valid IPv4 nor IPv6 literal and has no `:`, so it falls out of that branch to the same line 1688 instead of throwing. I also got the reason wrong for this one in the issue text.

Thanks for the offer to take a PR. I've sent #PR_NUMBER. It limits each IPv4 part to 0–255 with at most three digits. Leading zeros such as `001` are still accepted, as `getByName` parses them. It also requires a string containing a colon to start with a hex digit, `:` or `[`. It's a change to the pattern plus tests. Happy to adjust it, or drop it if you'd rather keep things as they are.
