Title: Volume-based cluster correction: null CSD uses 6-connectivity while
mri_glmfit-sim clusters the data with --allowdiag (releases <= 7.4)

**Summary.** In every release through 7.4.x, `mri_glmfit --sim` builds the
max-cluster null distribution with face-only (6) connectivity:
`clustGetClusters()` calls `clustGrow()` with `AllowDiag = 0`
(utils/volcluster.cpp, and `mri_glmfit.cpp:1893` in v7.4.1 passes no
AllowDiag). The `mri_glmfit-sim` script, however, clusters the observed map
with `mri_volcluster ... --allowdiag` (26-connectivity) before looking
cluster sizes up in that CSD (v6.0.0 script ~line 600; v7.1.1:640;
v7.4.1:674). An observed cluster can only be >= its 6-connected size, so
cluster-wise p-values are biased toward significance.

The current dev branch already fixes this (`--allowdiag` added to the
mri_glmfit sim path, with the comment "must match mri_volcluster"), so the
ask is: (1) a backported point release or at minimum a prominent release
note / wiki entry stating which released versions are affected, and (2) a
note in the mri_glmfit-sim help. Surface-based correction is unaffected
(both sides use mesh connectivity).

**Quantification** (Monte Carlo, 5,000 null + 5,000 test smoothed Gaussian
fields per condition, 64x64x40, one-sided, shipped p convention; scipy
structures identical to clustGrowOneVoxel's neighbor sets):

| Smoothness | CDT | achieved FWER @ nominal 0.05 (shipped) | matched 26/26 |
|---|---|---|---|
| FWHM 1.5 vox | z=2.3 | 0.193 | 0.057 |
| FWHM 2.0 vox | z=2.3 | 0.096 | 0.050 |
| FWHM 2.5 vox | z=2.3 | 0.084 | 0.057 |
| any | z=3.1 | no additional inflation from the mismatch | - |

A cluster at the true 5% critical size is reported as p = 0.008-0.033
depending on smoothness. The inflation is largest for minimally smoothed,
low-CDT volume analyses. Simulation script available on request.

**Affected:** any published volume-based `--sim mc-full`/`--perm` cluster
result from FS 5.3-7.4 at low cluster-forming thresholds.
